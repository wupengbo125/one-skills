# One Super-Me (超级我 / 逍遥)：数字化身与双通道记忆中枢

> **核心宗旨**：
> 1. **全域收敛**：智能体产生的所有记忆、文档与画像，**100% 收敛在 `$github_dir/one-hippocampus/`**，严禁污染用户个人知识库（如 `one-llmwiki`）。
> 2. **文档正名**：Hook 自动提炼出的成果是**「文档」**（操作方法、资源位置、关键事实），**绝非「skill」**。
> 3. **全中文规范**：所有记忆、索引与沉淀文档一律使用中文书写。

---

## 一、 核心愿景 (Vision)

One Super-Me 是用户的超级智能体工具与数字化身。
AI 拥有对人类用户的深度认知上下文：
* **用户基础画像**：知晓“我是谁”、生活与物理属性（例如车是电车还是油车）；
* **工程资产与路径**：知晓用户的 GitHub 根目录（`$github_dir`）、名下项目列表；
* **高频别名映射**：当用户说 `dot five` 等代号时，AI 秒懂对应哪个工程、在什么路径执行常用操作；
* **自驱动查文档办事**：用户让 AI 办事时，AI 直接在海马体中检索对应文档自主闭环，无需人工反复解释上下文。

---

## 二、 双通道记忆输入机制 (Two-Channel Ingestion)

```
                     ┌────────────────────────┐
                     │     用户交互与会话      │
                     └───────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼ (每轮 Hook 自动)              ▼ (主动显式指令)
        ┌──────────────────┐            ┌──────────────────┐
        │  提炼操作/位置文档 │            │  主动长文沉淀     │
        │ one-hippocampus  │            │ one-hippocampus  │
        │ /memory/         │            │ /onewiki/        │
        └────────┬─────────┘            └────────┬─────────┘
                 │                               │
                 │ (更新画像/近期)                │ (外层 index.md 索引)
                 ▼                               ▼
        ┌──────────────────────────────────────────────────┐
        │           $github_dir/one-hippocampus            │
        │                                                  │
        │  🔥 hot.md     : 用户纯手动管理，不限条数        │
        │  ⚡ recent.md  : 自动更新，双阈值(2个月/100条)淘汰 │
        │  ❄️ INDEX.md   : 全局冷知识与功能文档总索引      │
        │  👤 profile.md : 用户画像与项目代号(如 dot five) │
        └──────────────────────────────────────────────────┘
```

### 1. 通道 A：对话 Hook 自动提炼文档（被动潜意识）
* **运行机制**：每轮用户对话结束后，挂载的 Hook 钩子函数自动介入分析。
* **提炼内容（是「文档」，绝非「skill」）**：
  * **操作方法文档 (How-to)**：新事物怎么做、执行流程规范与排障步骤；
  * **资源定位文档 (Where-is)**：什么东西在哪里、路径配置、服务入口；
  * **事实与认知 (What-is)**：会话中透露的重要事实与上下文；
  * **用户画像同步**：自动补齐/更新用户的结构化画像与别名表。
* **存储位置**：`$github_dir/one-hippocampus/memory/` 与 `system/profile.md`。

### 2. 通道 B：用户主动触发沉淀（主动显意识）
* **运行机制**：非 Hook 方式，由用户明确下达记录、整理长文指令（如“记一下”、“沉淀到 Wiki”）。
* **存储位置**：**`$github_dir/one-hippocampus/onewiki/`**（智能体内部专区，严禁污染个人知识库）。
* **索引规范**：最外层维护 `index.md`，清晰索引每篇文章的功能与核心要点。

## 三、 全新海马体目录拓扑 (`$github_dir/one-hippocampus`)

彻底抛弃旧版历史包袱与复杂规则，采用纯净架构：

```
$github_dir/one-hippocampus/
├── INDEX.md                 # 海马体总索引：负责冷知识、各领域与全部文档总导航
├── hot.md                   # 热记忆：纯人工手动维护（不限条数），外部AI宿主永远常驻调用
├── recent.md                # 近期记忆：系统自动维护更新，双阈值（2个月 / 100条）淘汰
├── memory/                  # Hook 自动提炼的「文档」沉淀池（非 skill）
│   ├── methods/             # 操作方法文档：新事物怎么做、SOP 流程
│   ├── locations/           # 资源定位文档：什么东西在哪里、路径拓扑
│   └── facts/               # 事实与关键上下文文档
├── onewiki/                 # 主动沉淀文档专区（非 Hook，用户主动要求记录的长文）
│   └── index.md             # 索引 onewiki 下每篇文章的功能与摘要
└── system/
    └── profile.md           # 结构化用户画像（车型油电、路径、项目清单、dot five 别名映射）
```

## 四、 记忆分层与生命周期规则

### 1. 🔥 热记忆 (`hot.md`)
* **维护人**：**纯用户人工手动维护**；
* **容量限制**：**不限条数**，完全由用户自由控制；
* **装载机制**：外部 AI 运行框架全局永远自动装载调用，本技能内部无需重复调用。

### 2. ⚡ 近期记忆 (`recent.md`)
* **维护人**：**系统自动维护与更新**；
* **内容**：记录经常查用、近期活跃的实体、文档指针与事项；
* **条目格式**：`[实体/主题] | [对应文档指针/内容] | [最近访问时间 YYYY-MM-DD]`；
* **刷新机制**：命中或调用该条目时，即刻刷新时间戳为当天；
* **淘汰机制（双阈值“任一满足即清理”）**：
  * **时间上限**：条目最长保留 **2 个月（60 天）**；
  * **数量上限**：最多容纳 **100 条**（超额按 LRU 顺序淘汰）；
  * **触发规则**：只要满足“时间超过 2 个月”或“条数达到 100 条”的**任意一个条件**，立即触发清理。

### 3. ❄️ 冷记忆与冷知识索引 (`INDEX.md`)
* **核心定位**：本技能核心负责索引冷知识，对全局沉淀文档提供清晰导航。
