# One Super-Me 记忆中枢与三维记忆智能体需求文档

> **核心红线与核心规范**：
> 1. **全域收敛（数据仓与脚本职责划分）**：智能体产生的所有记忆、文档与画像，**100% 收敛在 `$github_dir/one-hippocampus/` 纯数据仓**；BM25 检索、同步建库与记忆治理等能力**收敛在 Skill 辅助脚本 `scripts/super_me.py`**（非复杂客户端/服务端，即开即用）；
> 2. **三维沉淀架构**：严谨区隔“自动记忆（伴随增量）”、“收工记忆（无脑收工）”与“避坑手册（经验规程）”，AI 在会话中各司其职、精准沉淀；
> 3. **严格意图触发**：仅支持明确的用户意图触发（自动伴随记录、手动“收工”/“超级我”、规程“记一下”/“避坑手册”），严禁引入虚构无意义的暗号或触发词；
> 4. **中文文章命名**：顶层骨架英文，**所有具体文档与文章文件名必须 100% 使用中文**；
> 5. **分立数据层拓扑**：严格分立 `system/`（画像/拓扑/代号/宪法）、`memory/`（单层扁平情景记忆）与 `onewiki/`（按领域分类的私有 Skill 避坑手册库）；
> 6. **BM25 极速全文检索**：新增/更新内容由 AI 写入 Markdown 后调用脚本增量同步本地数据库 `.fts.db`；该数据库由 `.gitignore` 忽略严禁加入 Git；AI 查记忆**优先直接 BM25 检索关键词**；
> 7. **近期记忆置顶与双阈值治理**：`recent.md` 记录近期活跃流水，凡访问/写入条目立即刷新时间戳并置顶到表格首行，严格执行“超 60 天”与“超 100 条”LRU 淘汰。

## 1. 背景与愿景 (Vision)

构建专属于用户的超级智能体工具与数字化身（One Super-Me）。
**愿景目标**：
在独立的海马体仓库（`$github_dir/one-hippocampus/`）中沉淀 AI 对人类用户的全部记忆与文档：
- **用户基础画像**：我是谁、生活与物理属性（如硬件配置、常用环境）；
- **工程资产与路径**：用户的 GitHub 仓库根目录（`$github_dir`）、名下项目列表；
- **高频别名与操作映射**：用户说 `OneToDo`、`vfrp` 等高频代号时，AI 能够立即知道对应哪个工程、在什么路径执行常用操作；
- **自驱动查手册办事**：用户让 AI 干某件事时，AI **优先通过 BM25 本地检索**，直接在海马体中查到对应独家实操手册（我电脑上有啥、怎么做、在哪里）去执行，无需人工反复解释。

## 2. 交互机制：三维记忆沉淀机制 (Three-Channel Ingestion)

所有内容均统一保存在 `$github_dir/one-hippocampus/` 下，具体文章全部使用中文。分为三条独立的运作链路：

### 2.1 模式一：自动记忆（主航道，编码推进中伴随增量追加）
* **触发机制**：日常编码推进中产生实质代码修改、配置变更或架构决策时，AI 主动触发，不依赖用户提醒。
* **处理逻辑**：
  1. 检查 `memory/` 是否已存在当天同主题文件；若无则创建 `memory/<YYYY-MM-DD_中文主题>.md`，若有则增量追加；
  2. 记录刚才改了什么、为什么改、遇到了什么坑、当前状态如何（保留演进过程，不全量推倒重写）；
  3. 执行脚本流水打卡与置顶：
     ```bash
     python3 scripts/super_me.py recent "<中文主题>" "memory/<YYYY-MM-DD_中文主题>.md"
     ```
  4. 增量同步索引：
     ```bash
     python3 scripts/super_me.py sync "memory/<YYYY-MM-DD_中文主题>.md"
     ```

### 2.2 模式二：收工记忆（显式触发，无脑收工）
* **触发机制**：用户在会话结束前随手一句“**收工**”、“**超级我**”。
* **阶段 1：防垃圾过滤门禁 (Junk Filter Gate)**：
  - AI 自行审视本次会话全过程（改动文件、工具调用、交流事实）；
  - **宁缺毋滥**：若只是日常闲聊吹水、简单问答、无新工程事实、无硬核改动，**绝不记录任何垃圾**，直接一句话退出，零文件落盘；
  - 若今日进展已在自动伴随记忆中完整覆盖，直接极简确认退出。
* **阶段 2：情景记忆连贯落盘（像人类一样记事）**：
  - 拒绝机械切碎抽取实体碎片（不搞死板的 methods/locations/facts 抽取）；
  - 连贯撰写本次会话的实操复盘长文至 `$github_dir/one-hippocampus/memory/<YYYY-MM-DD_中文主题>.md`（包含背景目标、决策踩坑复盘、落地改动清单与避坑要点）；
  - 调用脚本流水打卡、置顶并治理近期记忆：
     ```bash
     python3 scripts/super_me.py recent "<中文主题>" "memory/<YYYY-MM-DD_中文主题>.md"
     python3 scripts/super_me.py sync "memory/<YYYY-MM-DD_中文主题>.md"
     ```
  - 极简一句话汇报。

### 2.3 模式三：避坑手册（显式指令沉淀经验规程）
* **触发机制**：由用户明确下达记录、整理长文指令（如“**记一下**”、“**记到文档**”、“**避坑手册**”、“**存手册**”）。
* **处理逻辑**：AI 根据用户指令直接撰写领域分类的私有技能手册。
* **落盘目标**：写入 **`$github_dir/one-hippocampus/onewiki/<领域分类>/<中文手册名称>.md`**，并在 `onewiki/index.md` 对应领域下登记一行。
* **即时同步**：保存入库后，立即调用：
  ```bash
  python3 scripts/super_me.py sync "onewiki/<领域分类>/<中文名称>.md"
  python3 scripts/super_me.py sync "onewiki/index.md"
  ```

## 3. 全文检索与脚本规范 (`scripts/super_me.py`)

### 3.1 脚本规范与定位
* 拒绝复杂的“客户端/服务端”多层封装，在 Skill 的 `scripts/` 目录下提供单一自包含 Python 脚本：`scripts/super_me.py`；
* 用户环境可通过软链接/包装器使用 `super-me` 全局简写命令调用；
* 数据库文件 `.fts.db` 存储在海马体仓库根目录下，由 `.gitignore` 忽略，不进入 Git 仓库。

### 3.2 子命令规格

| 子命令 | 参数 | 说明 |
| :--- | :--- | :--- |
| `search` | `<关键词>` | BM25 全文检索：基于 CJK 双字与英文词分词，毫秒级输出相关度评分与高亮片段。 |
| `recent` (别名 `touch`) | `<实体/主题> [指针/简述]` | 近期活跃流水打卡：刷新条目时间戳为今天并移到表格第一行（置顶）；自动执行 60 天/100 条双阈值淘汰与 `recent.md` 索引同步。 |
| `clean` | 无 | 手动治理近期记忆：扫描 `recent.md`，淘汰超 60 天与超 100 条记录，并同步索引。 |
| `sync` | `<相对路径>` | 增量同步单篇 Markdown 文档到 `.fts.db`；文件删除时清理对应记录。 |
| `rebuild` | 无 | 全量扫描海马体目录重建 `.fts.db` 数据库。 |

### 3.3 检索寻路优先级
当 AI 执行任务或查询用户记忆时，遵循以下优先级：
1. **第一优先级（高频代号消歧）**：查阅 `system/aliases.md` 获取明确项目路径与动作；
2. **第二优先级（BM25 极速检索）**：调用 `python3 scripts/super_me.py search "<关键词>"` 秒出命中段落，零 Token 消耗；
3. **第三优先级（语义兜底）**：若未命中，降级回退至大模型语义理解能力，扫描 `INDEX.md` 与 `onewiki/index.md`；
4. **第四优先级（活跃记忆）**：结合 `hot.md` 与 `recent.md` 进行意图消歧与上下文唤醒，命中时即刻打卡置顶。

## 4. 存储架构：海马体纯数据仓 (`$github_dir/one-hippocampus/`)

```
$github_dir/one-hippocampus/
├── .gitignore               # 明确忽略 .fts.db 本地检索库
├── .fts.db                  # 本地 BM25 检索数据库（本地存在，不入 git）
├── INDEX.md                 # 海马体总索引：全局模块导航与冷知识入口
├── hot.md                   # 热记忆：纯用户手工维护（不限条数），常驻调用
├── recent.md                # 近期记忆流水：双阈值（60天/100条）控制，访问置顶
├── system/                  # 用户系统配置与基准
│   ├── constitution.md      # 行为宪法（来自 one-agents.md）
│   ├── profile.md           # 基础画像、网络拓扑、常驻端口与仓库路径
│   └── aliases.md           # 项目代号与高频指令映射表（如 OneToDo、vfrp）
├── memory/                  # 情景记忆（纯单层扁平，按时间连贯叙事，拒绝碎片抽取）
│   └── YYYY-MM-DD_中文主题.md # 会话实操长文复盘（背景、决策、改动、避坑）
└── onewiki/                 # 领域避坑手册库（按领域分类，全部中文命名）
    ├── index.md             # 避坑手册总大纲与领域索引
    ├── 网络/                # 代理、穿透、DNS、路由等实操规程
    ├── 硬件/                # 显卡、电源、硬件排障等实操规程
    └── AI/                  # 模型、网关、Token 等配置实操规程
```

## 5. 近期记忆生命周期与治理规范 (`recent.md`)

* **存储位置**：`$github_dir/one-hippocampus/recent.md`
* **条目格式**：`| 实体 / 主题 | 对应文档指针 / 内容简述 | 最近访问时间 |`（日期格式：`YYYY-MM-DD`）
* **置顶刷新机制 (LRU Top)**：
  - 无论新增条目或对已有条目进行查用与访问，访问时间戳均更新为当天，并立即移动至表格第一行（表头下方）。
* **淘汰规则（双阈值控制）**：
  1. **时间阈值**：仅保留最近 60 天内的条目，超过 60 天的记录自动清理；
  2. **条数阈值**：全表最大保留 100 条记录，超出部分按访问时间降序截断；
  3. **自动化执行**：由 `scripts/super_me.py recent` 自动级联触发清理并完成索引同步。
