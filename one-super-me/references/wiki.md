# 踩坑记录与避坑要点（Wiki 手册）

本路线负责将**踩坑记录、排障过程、解决方案、环境配置、操作规程** 等可复现的工作流记录到 `onewiki/` 下的私有技能手册。

- 遭遇复杂配置或踩坑，需要长期保留标准操作步骤。
- 发现通用运维规程、故障排查清单、环境快速部署指南。
- 已有成熟可靠的解决方案，可以标准化为本机 SOP。

## 工作流

### 1. 识别沉淀对象
- 是否为**本机特定环境下的操作**？（如显卡管理、代理配置、本地 AI 网关）
- 是否**可复现、有标准步骤**？（非一次性排障）
- 是否**未来会频繁复用**？（值得文档化）

若全部满足 ➔ 进入沉淀流程。

### 2. 确定领域分类

根据内容性质，选择或新建对应领域目录。当前主要分类：

| 领域目录 | 包含内容 | 示例 |
| :--- | :--- | :--- |
| `技术/` | 网络、硬件、AI 等技术 SOP | FRP 穿透、代理配置、显卡管理 |
| `炒股/` | 交易规程、风险清单 | （按需新建） |
| `英语/` | 学习方法、常见表达 | （按需新建） |
| `感悟/` | 个人反思、决策记录 | （按需新建） |

### 3. 组织文件与命名

- **文件路径**：`onewiki/<领域>/<主题>.md`
- **文件名规范**：清晰的中文名，如 `FRP内网穿透与多端口映射配置.md`
- **内容结构**：
  ```markdown
  # <标题>
  
  > **核心解决**：一句话概括这份文档解决什么问题。
  
  ## 前置条件
  - 环境要求、依赖项、权限要求
  
  ## 标准步骤
  - 分步详细步骤，包含命令、配置文件路径、预期结果
  
  ## 故障排查
  - 常见错误与解决方案
  
  ## 后续维护
  - 如何验证、如何回滚、定期巡检建议
  ```

### 4. 更新主导航

编辑 `onewiki/index.md`，在对应领域下添加链接与概要：

```markdown
## 🛠️ 1. 技术 (Technology)

- [文件名](./技术/文件名.md)
  - **核心解决**：简述这份文档的价值。
```

### 5. 提交与同步

```bash
git add onewiki/
git commit -m "docs(wiki): 新增/更新 <领域>/<主题>"
git push
```

## 与其他路线的协作

- **自动记忆** → 会话中发现可复现 SOP ➔ 在 `memory/` 里记录实操演化后，稍后沉淀为 `onewiki/` 手册（两步沉淀）。
- **手工记忆** → 收工复盘时发现新规程 ➔ 先补全 `memory/` 长文，再从中提炼为 `onewiki/` 手册。
- **one-wiki 编译** → `onewiki/` 完全独立维护（手工编辑），`one-wiki` Skill 不负责编译这层。

## 什么不放入 Wiki

- **一次性排障日志**：放入 `memory/`。
- **临时配置或试验**：放入 `memory/`。
- **外部第三方文档**：放入 `raw/` 或外部知识库，不复制进 `onewiki/`。
- **过时失效的方案**：删除或标记为 `[已废弃]`，注明原因与日期。
