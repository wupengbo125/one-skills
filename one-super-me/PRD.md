# One Super-Me 记忆中枢与双链路智能体需求文档

> **核心红线与核心规范**：
> 1. **全域收敛（数据仓与应用层分离）**：智能体产生的所有记忆、文档与画像，**100% 收敛在 `$github_dir/one-hippocampus/` 纯数据仓**，严禁写入个人知识库；BM25 检索、同步建库与记忆治理能力**100% 收敛在当前 Skill 统一引擎**（`super-me` CLI）；
> 2. **双模式沉淀架构**：严格区隔“显式记录链路”与“无脑收工链路”，AI 在会话中各司其职、精准沉淀；
> 3. **中文文章命名**：顶层骨架英文，**所有具体文档与文章文件名必须 100% 使用中文**；
> 4. **分立数据层拓扑**：严格分立 `system/`（画像与代号）和 `memory/`（四维知识库），`onewiki/` 专供单层平铺避坑长文；
> 5. **CLI BM25 极速检索**：新增/更新内容由 AI 直接写入 Markdown 并调用 `super-me sync <相对路径>` 增量同步本地数据库 `.fts.db`；**该数据库严禁加入 Git**；AI 查记忆**优先直接 BM25 搜关键字**。
---

## 1. 背景与愿景 (Vision)

构建专属于用户的超级智能体工具与数字化身（One Super-Me）。
**愿景目标**：
在独立的海马体仓库（`$github_dir/one-hippocampus/`）中沉淀 AI 对人类用户的全部记忆与文档：
- **用户基础画像**：我是谁、生活与物理属性（例如车是电车还是油车等）；
- **工程资产与路径**：用户的 GitHub 仓库根目录（`$github_dir`）、名下项目列表；
- **高频别名与操作映射**：用户说 `OneToDo`、`vfrp` 等高频代号时，AI 能够立即知道对应哪个工程、在什么路径执行常用操作；
- **自驱动查手册办事**：用户让 AI 去干某件事时，AI **优先通过 super-me BM25 本地快速检索**，直接在海马体中查到对应独家实操手册（我电脑上有啥、怎么做、在哪里）去执行，无需人工反复解释。

---

## 2. 交互机制：双链路记忆沉淀机制 (Dual-Pathway Ingestion)

所有内容均统一保存在 `$github_dir/one-hippocampus/` 下，具体文章全部使用中文。分为两条完全独立的运作链路：

### 2.1 链路 A：显式记录链路（人类指令让记东西）
* **触发机制**：由用户明确下达记录、整理长文指令（如“帮我记东西”、“记到文档里”、“记一下”、“沉淀避坑手册”）。
* **处理逻辑**：AI 根据用户指令直接撰写单层平铺的专属实操手册或方法总结。
* **落盘目标**：
  1. **避坑实操手册**：写入 **`$github_dir/one-hippocampus/onewiki/<中文手册名称>.md`**，并在 `onewiki/index.md` 登记一行（解决什么操作、对应什么本地资产）；
  2. **专项方法沉淀**：若属于特定操作步骤，存入 `memory/methods/<中文主题>.md`。
* **即时写库**：保存入库后，立即调用 `super-me sync "onewiki/<中文名称>.md"` 增量同步 BM25 索引。

### 2.2 链路 B：无脑收工链路（会话结束零心智负担随手收工）
* **触发机制**：用户在会话结束前随手一句“**超级我**”、“**收工**”、“**下班**”，用户不费心思考。
* **阶段 1：防垃圾过滤门禁 (Junk Filter Gate)**：
  - AI 自行审视本次会话全过程（改动文件、工具调用、交流事实）；
  - **宁缺毋滥**：若只是日常闲聊吹水、简单问答、无新工程事实、无硬核改动，**绝不记录任何垃圾**，直接一句话退出，零文件落盘。
* **阶段 2：四维认知精准提炼（有硬核产出才记录）**：
  - 👤 **画像与偏好 (Profile)**：提取用户的新习惯、硬件、开发偏好，追加更新至 `system/profile.md`；
  - 🗺️ **资产位置与代号 (Locations & Aliases)**：提取机器 IP、端口、工程路径写入 `memory/locations/<中文主题>.md`，新项目代号追加至 `system/aliases.md`；
  - 🛠️ **独家操作方法 (Methods)**：提取跑通的实操命令与踩坑经验，写入 `memory/methods/<中文主题>.md`；
  - ⚡ **核心实操流水 (Recent)**：提取会话时间、核心操作与改动，在 `recent.md` 表格追加一行。
* **阶段 3：同步与治理**：
  - 针对更新的文件分别执行 `super-me sync "<相对路径>"`；
  - 根据近期流水规模按需执行 `super-me clean` 触发双阈值淘汰。

## 3. 全文检索与统一 CLI 引擎 (Engine & BM25)

### 3.1 核心 CLI 引擎 (`one-skills/one-super-me/super-me`)
* 检索工具、增量同步、全量重建与生命周期清理完全由统一的 `super-me` 实现，海马体仓库内不保留多余执行脚本；
* 数据库文件 `.fts.db` 保存在海马体根目录下，由 `.gitignore` 全局忽略，不进入 Git 仓库。

### 3.2 检索优先级策略（BM25 优先秒搜）
* 当 AI 执行任务或查询用户记忆时：
  1. **第一优先级（最快）**：优先通过 `system/aliases.md` 查代号，或直接调用 `super-me search "<关键词>"` 进行 BM25 极速全文检索，毫秒级定位候选文档与关键段落；
  2. **第二优先级（高频路由）**：结合 `hot.md` 与 `recent.md` 进行意图消歧与路由；
  3. **第三优先级（结构导航）**：通过 `INDEX.md` 与 `onewiki/index.md` 查阅分类手册。

## 4. 存储架构：海马体纯数据仓 (`$github_dir/one-hippocampus/`)

```
$github_dir/one-hippocampus/
├── .gitignore               # 明确忽略 .fts.db 等本地检索库
├── .fts.db                  # 本地 BM25 检索数据库（本地存在，不入 git）
├── INDEX.md                 # 海马体总索引：负责冷知识、各模块与全局文档总导航
├── hot.md                   # 热记忆：纯用户手工维护（不限条数），外部AI宿主永远常驻调用
├── recent.md                # 近期记忆：系统自动维护更新，双阈值（2个月 / 100条）淘汰
├── system/                  # 用户系统配置
│   ├── profile.md           # 基础静态画像（车型油电、主力开发环境）
│   └── aliases.md           # 项目代号与高频指令映射表（如 OneToDo、vfrp）
├── memory/                  # 伴随沉淀文档池（按中文主题聚合，非 skill）
│   ├── methods/             # 操作方法：如《本地服务部署与重启.md》
│   ├── locations/           # 资源定位：如《局域网机器与服务端口.md》
│   └── facts/               # 事实认知：如《量化回测基本规则.md》
└── onewiki/                 # 内部实操手册（单层平铺，全部中文命名）
    ├── index.md             # 避坑手册索引清单
    ├── FRP内网穿透与多端口映射配置.md
    └── WSL环境显卡驱动配置备忘.md
```

## 5. 生命周期与淘汰机制 (recent.md 治理)

* **存储位置**：`$github_dir/one-hippocampus/recent.md`
* **淘汰规则（双阈值控制）**：
  1. **时间阈值**：仅保留最近 2 个月（60 天）内的条目，超过 60 天的记录自动清理；
  2. **条数阈值**：全表最大保留 100 条记录，超出部分按时间倒序淘汰最旧记录；
  3. **触发机制**：调用 `super-me clean`，任一条件满足即执行清理。
