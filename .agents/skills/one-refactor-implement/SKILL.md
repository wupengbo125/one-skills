# Faithful Refactor

根据用户指定的当前会话、需求文档或直接指令实施代码修改。前置调用 `/one-minimal-implement` 贯穿极简交付与范围控制。完整实现全部需求，绝不增加范围外功能。遇歧义先询问。

## 零脑补重写与剪贴板优先原则 (Clipboard-First Rule)

在合并、重构、迁移或引用已有代码时，**绝对禁止凭记忆在内存中重新打字生成已有代码**（极易产生遗漏与漏洞缝合怪）。

必须像人类程序员使用 `Ctrl+C / Ctrl+V` 剪贴板一样，采用物理方式处理代码：
- **全文件复用**：直接用 `cp` / `mv` 进行物理复制，作为修改基准。
- **片段抽取与粘贴**：必须用行号物理截取代码片段再插入目标位置（例如 `sed -n '10,20p' src.py` 截取，`sed -i '5r /dev/stdin' target.py` 插入），**严禁凭记忆手敲重写**。

### 物理合并 5 步规范
1. **前置准则**：调用 `/one-minimal-implement`，在重构与合并全过程中贯穿极简代码与 0->1 精准交付规范。
2. **物理基准复制 (`cp`)**：选择主体文件直接复制作为唯一基准。
3. **定位插入点**：精确定位需嵌入片段的目标文件及具体行号/插入位置。
4. **精准抽取粘贴**：从源文件中原封不动提取目标代码块，精准物理插入，**严禁凭大脑记忆重新打字大段内容**。
5. **外科手术级修整**：仅对 Frontmatter、衔接变量或必要的极少数行进行微创修整，确保运行正常。

### 约束与验证
- **非修改区绝对禁触**：未变动代码严禁重新打字，只对差异点进行精准物理修改。
- **测试与审查**：优先使用 `/tdd`。完成后使用 `/code-review` 审查，只修复本次需求相关问题。
- **提交检查**：确认需求全覆盖、无额外改动、测试全通过后提交。
