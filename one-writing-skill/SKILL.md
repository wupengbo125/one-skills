写任何 Agent 会读的文档时都适用：skill、AGENTS.md/CLAUDE.md、被指针引用的文档。打包方式不同，写法一样——Agent 每次跑同一个**流程**，不是产出同一个结果。

如果写的是 skill，格式细节（YAML 头、触发方式、路由技能）见 [references/mechanics.md](references/mechanics.md)。

## 上下文指针

**上下文指针**是 Agent 上下文里的一句话，指明某个不在上下文里的材料，并写清楚什么条件下才去读它。skill 的 description 就是一种；AGENTS.md 里点名某个文档的一行也是。指针的**措辞**（不是它指向的目标）决定 Agent 什么时候、多可靠地去读那份材料。一个必读的材料配了一句含糊的指针，就是变异 bug：先把措辞磨利，磨不出来再把内容内联。

一个指针干两件事：说清材料是什么，列清楚触发去读它的**分支**（一个分支 = 文档处理的一种不同情况，不同跑法走不同路径）。常驻指针每个词都在每轮花 token，比正文更要狠剪：

- **首词前置**：指针的触发作用就在首词。
- **一个分支一个触发词**：同义词重写同一个分支 = 写两遍，合并成一个。
- **砍掉正文已经说过的身份信息**。

## 两种负担

每个文档和指针花两种预算：

- **上下文负担**：常驻材料每轮占 token 和注意力的成本——AGENTS.md 一行、skill 的 description，不管触发不触发都花。
- **认知负担**：给人的成本——有哪些文档、什么时候该翻哪个。人就是索引。这个不用最小化，是人的能动性的代价；在需要人判断的地方花，不需要的地方去掉。

只被指针触发才加载的材料，只付指针那一行的上下文负担；没有指针的材料全靠认知负担。

## 信息分层

文档由两种内容构成：**步骤**（Agent 按序执行的动作）和**参考**（按需查的定义、规则、事实）。两者随便混：全步骤（菜谱）、全参考（审查规则）、或混合。核心决策是把每块放在**信息分层**的哪一级，按 Agent 多急需这材料排：

1. **文件内步骤**：主级，Agent 按序做什么。
2. **文件内参考**：按需查。经常是一个合法的平铺兄弟集合（审查的所有规则在同一级），这是合理安排，不是坏味道。
3. **披露参考**：推到单独文件，靠上下文指针触达，指针触发才加载。从同文件夹的兄弟文件到全仓库任何位置都能指。

推得太少顶层臃肿，推得太多藏了 Agent 真需要的东西。这个张力就是全部决策。

**渐进披露**是往下推（挪出主文件、藏到指针后），让顶层保持可读。不主要是省 token：是保护分层。分支是最干净的披露测试：每个分支都要用的内联，只有部分分支用的推到指针后。当文档有步骤时，本该披露的文件内参考会把步骤埋掉，让"注意它"变成抛硬币——这是变异杠杆，不只是可读性问题。

**同处一穴**是文件内的配套动作：分层决定**往下推多远**，同处一穴决定**在那一级旁边放什么**。一个概念的定义、规则、注意事项放同一标题下，别散着——读一处就把邻居带出来。测试：文档读起来像写给 Agent 的文档。分组的读起来像，散的不像。（和重复不同：重复是同一个意思写两处；散落是一个意思碎在多处。）

**臃肿**是这里的失败模式：文档单纯太长，即使每行都活、都唯一。注意力被稀释，多一行就多一行要保持相关。解药就是分层：参考推到指针后，按分支或顺序切，每条路径只带自己需要的。

## 步骤和完成标准

每个步骤以**完成标准**收尾，告诉 Agent 什么时候算做完。两个属性让它成为杠杆：

- **清晰**：Agent 分得清做完没？模糊的边界（"理解到位了"）招**提前完成**——在真做完之前就停，注意力滑向"已经做完"。还在前面的步骤可见性（**后完成步骤**）提供拉力；标准的清晰度是阻力。防守顺序：先磨利边界（本地、便宜）；只有它确实模糊到改不动、而且你观察到赶工时，才通过拆序列把后面的步骤藏起来。藏只在真正的上下文边界跨过时有效（交接或子 Agent 派发；内联调用不把后续步骤移出上下文，什么都不清）。
- **要求**：要求多深。"每个改到的模型都核对过"逼着做透，"产出一份变更清单"不会。要求驱动**额外工作**（Agent 在任务里要挖的东西，藏在措辞里、不写成单独一步），而且不限于步骤："每条规则都用了"绑住平铺的参考体，就像"每步都做了"绑住序列——这就是为什么纯参考文档也能带穷尽性门槛。

最强的标准既可检查又穷尽。

## 什么时候切分

把一个文档切成两个花一种负担，所以只有切得值才切：

- **按顺序切**：在后完成步骤会让 Agent 抢当前步的地方切开。后面的看不见，逼它在当前步做透。小心反向：合并序列会把后续步骤暴露给下一步，招提前完成。
- **按触发切**：skill 专属，见 [references/mechanics.md](references/mechanics.md)。

## 引导词

**引导词**是个模型预训练里已有的紧凑概念（lesson、fog of war、tracer bullets），Agent 跑文档时用它思考。重复作 token、不作句子，它积累一个分布式定义，用最少的 token 锚住一整块行为——直接征用模型已有的先验。自己造词也行，但要定义清楚，可造词征用不到先验：定义花的 token 是预训练词白送的；先找已有的词。

它锚两次。正文里：**执行**——每次出现都触发同一行为；平铺参考里：把注意力集中到要找的那类东西上。指针里：**触发**——同一个词活在你的 prompt、文档、代码库里，Agent 把这共享语言和材料挂上钩，触发更可靠。

找机会用引导词重构。三联词在三处展开、指针花一句话比划一个概念。每个都是等着塌成单 token 的段落：

- "快、确定、低开销" → `tight`（一个 tight 循环）。
- "一个你信的循环" → `red`，把模糊门槛变成二元可观测状态（循环在 bug 上 red 了，或没 red）。

你赢两次：token 更少，Agent 挂思考的钩子更尖。假设每份文档都带着引导词能退休的重述。去找。

**否定**是这个杠杆旁边的失败模式：靠禁令转向会把被禁的行为拉进上下文，让它**更**可用，不是更不可用。"别想大象"，满脑子就是大象；否定是弱修饰，被强激活的概念冲垮，所以禁令读起来像"去做那事"的指令。**肯定地写**：说出目标行为（"写单行注释"），被禁的就永远不被提起。禁令只在没法正面说的硬护栏时有位置；即便那样，也配上正面目标，让注意力落在要做的事上。

## 修剪

- 每个意思保持**单一事实来源**：一个权威位置，改行为就是改一处。**重复**（同一个意思在多处）花维护和 token 成本，还把一个意思在分层上抬过它真实的等级。（引导词的反面：引导词有意重复 token、永不重复意思。）
- **环境**也是事实来源（package.json scripts、配置文件、目录布局、--help 输出），文档复述它就是**缓存**：一份查表副本，只有查表贵时才值。缓存 Agent 查不到的：没写的约定、选择背后的原因、配置不会招的坑。一文件一命令的查表留给环境，不会过期。
- 每行查**相关性**：它还和这文档干的事有关吗？一行从不沾任务（纯 exposition、或该被披露的分支）、或随行为/世界变化过期，就失去相关性。越短的文档越容易保持相关。没有修剪纪律，默认下场是**沉积**：旧层一层层堆着，加感觉安全、删感觉冒险，直到你得挖穿它们才找得到活的。
- 逐句找**空操作**：模型默认就遵守的指令，写出来花负担却什么也不说。测试（它相对默认改不改行为？）是相对模型的，不是相对读者的：两个人对某句是不是空操作意见不同，别靠辩论定，跑一下文档。一句不合格，**整句删**，别只减字。这个测试也评引导词：一个弱到打不过默认的词（"要透彻"——Agent 已经差不多透彻了）是空操作，解法是更强的词（"无情"），不是换技法。
