# 249999b0 会话案卷：Moshi 左右切换失败排障与卷轴封存

## 背景诉求
iPhone 上 Moshi 连本机进 Herdr 后左右滑动，弹「无法切换窗口 / Moshi 无法确认复用器状态，请检查 app hook」，且"经常出现"。用户要求查清原因，最后要求把过程封存为卷轴（标题用户指定：「关于 moss 左右切换失败的问题」，只记关键）。

## 排查过程
1. 先怀疑 Tailscale SSH 抢占 tailnet 22 端口（`RunSSH: true`，手机会话确由 tailscaled 起 `login -f`），做了双端口改造（22 保留 Tailscale 原生鉴权，sshd 新绑 tailnet IP:2222 给 Moshi）。**实测排除**：Tailscale SSH 会话下 `moshi-hook context --ssh-connection` 能正常返回 `kind=herdr`。
2. 又怀疑 herdr 版本 / 多客户端共享视图，把 herdr `0.8.2 → 0.9.0`（live handoff）。**问题依旧**，排除。
3. 关键手段：给 `moshi-hook.service` 加 drop-in 开 `-v`，复现后日志直接给出真凶：
   `context request failed ... sshConnection="\x1b[?1000l\x1b[?1002l\x1b[?1003l\x1b[?1006l100.113.223.11 51453 ..."`。
4. 本地 pty 复现确认（`script -qec 'bash -ic ...' | cat -v`），污染串与 `dotfiles/rc/bash/bashrc.personal` 末尾的 `printf '\e[?1000l\e[?1002l\e[?1003l\e[?1006l'` 逐字节一致。

## 根因
交互式 shell 启动时那行 printf 的输出**紧贴** shell 第一条命令输出、中间零分隔符；Moshi 开会话读 pty 抓 `$SSH_CONNECTION`，把 ESC 串粘到客户端 IP 前 → 缓存脏值 → 该会话内每次滑动查状态都 `no process with SSH_CONNECTION=<脏值>` → 弹报错。脏值跟着会话走、不自愈；抓取与启动输出存在时序竞态，故"经常而非总是"。

## 关键决策
- 修复只删那行 printf（原地留"勿加回"注释），鼠标模式重置改为按需函数 `mouseoff()` 放 `rc/bash/functions`（函数定义不产生输出）。
- 修完后报错"变了"，经查是**空集**而非新故障：当时 herdr 只有 1 个 tab，状态确认成功但无目标可切；日志指纹为短时间内连续多次 `tab.focus` 指向同一 tab。用户建出第 2 个 tab 后即恢复正常。
- 双端口改造保留（22 Tailscale 原生鉴权 / 2222 系统 sshd 给 Moshi），并补 `~/.profile` 的 LANG 默认值（普通 sshd 不像 Tailscale SSH 会注入 LANG，缺则中文乱码）。
- 顺带修掉 PATH 九重重复（幂等 `path_add` + 收尾去重），与本次故障无关，见 dotfiles。
