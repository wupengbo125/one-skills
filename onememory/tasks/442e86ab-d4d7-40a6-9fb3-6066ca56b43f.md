## 背景诉求
用户一句话：待办插件的开场向导词现在三种模式（普通 / 赛马 / 委员会）共用一份，要拆成独立的三份，各模式用自己的那份。内容他不care——"做好了之后我自己去改它的内容"。

## 关键决策
- 拆成三个模板键：initial（普通）/ initialRace / initialCommittee，各存一个 md 文件。
- 初始内容照抄现有普通那份（用户拍板），不做内容设计。
- 三份对等入库（最终定案）：赛马 / 委员会两份不再"首次用到才照抄生成"，三份都是仓库资产、待遇完全相同；删掉生成兜底逻辑与 prompts/.gitignore。
  - 教训：用户说"分成 N 份"＝N 份完全对等，不能做成分主副两级（一份入库、其余派生/忽略）。评审把这条列成 [建议] 并给了两个选项，我选了生成那个，属于我自己判断失误。
- 模式判定统一到 shared/initialKindOf（赛马优先、其次委员会）：界面挑哪份编辑、派马挑哪份拼，共用一处判断，避免两边顺序不一致。

## 评审三轮的整改（都是派马提示词相关的坑）
- 切模式时未保存的改动留成草稿并提示一次；恢复草稿要同步"这份已加载"标记，否则加载分支会用服务器原文盖掉草稿。
- 编辑框是不受控输入（initial 只在挂载生效）：换模式必须靠 key 重挂，且内容没到手前先清空 + 锁住 editable，否则会把上一份的字写进这一份。
- 模板目录写不进时保留降级（能看能改），只有真保存时才明确报错。
- 关掉弹层时模式回普通，不算"切模式"：草稿和未保存标记一并收干净。

## 代码结论
- server/review.ts：TEMPLATE_NAME / 模板名标签 / defaultText（变体照抄普通那份）/ writeTemplate（失败明说）。
- server/executor.ts：派马时按 initialKindOf 挑对应那份拼在提示词最前。
- client/todo.tsx：按模式取模板、草稿按模式留、输入框 key + editable。
