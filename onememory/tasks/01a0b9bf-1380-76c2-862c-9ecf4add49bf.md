## one-orca-race：CodeBuddy 建不出终端

背景诉求：用户反馈 one-orca-race 技能里新建 CodeBuddy 建不出来，要求实测。

排查过程：
1. `race -a codebuddy -p ...` 报「创建终端失败」，worktree 却建成功了 → 说明卡的不是建 worktree
2. 手工复现 `orca terminal create --worktree "branch:race-x-1-codebuddy"` → `selector_not_found`。查 `orca worktree list`：Orca 建的分支是 `refs/heads/wupengbo125/race-x-1-codebuddy`，带命名空间前缀，脚本拼的 `branch:` 选择器匹配不到
3. 验证 `--agent codebuddy` → `Unknown TUI agent "codebuddy"`；Orca 包（app.asar）搜 `codebuddy` 零命中
4. 曾据此推断 Orca 里 CodeBuddy 的 id 是 `prime-agent`，并提议加软链 —— **被用户驳回**：prime-agent 是 2026-08 的独立 Agent 产品，与 CodeBuddy Code 无关，软链等于让 Orca 拉起错误产品。已更正 rules.md 与海马记忆
5. 信任弹窗：CodeBuddy 首次在新目录启动弹 "Do you trust the files in this folder?"，prompt 会被吞掉。先试 `orca terminal wait --for tui-idle` 再回车 → 无效（tui-idle 在 TUI 绘制前就返回）；再试 `read | grep -q` → 永远假阴性（pipefail + grep 提前关管道）；最终改为轮询 `terminal read` 文本 + 字符串匹配

关键决策：CodeBuddy 在 Orca 里无 agent id，只能走 Terminal 方式（建裸 worktree → terminal create 跑 `codebuddy` 命令 → terminal send 发 prompt），与用户记忆一致。

代码结论（`scripts/race`）：
- 终端定位改用 `worktree create --json` 返回的 `result.worktree.id`（`id:` 选择器），顺带修好 `claude:model` 等带参原生 agent 的 fallback 路径
- 后台轮询 60s 检测 trust 弹窗，命中则回车确认，再发 prompt
- 无参数执行直接输出用法帮助

涉及产物：`one-orca-race/scripts/race`、`onememory/rules.md`、`BLUEPRINT.md`

## 命名格式（用户后续追加）
- 终端标题与分支/worktree 名统一为 `🐎-agent名-Issue标题`（用户原话「把这个 race 7195 这块也改成那个格式」，确认连 git 分支名本身一起改）
- 分支里空格与 `/` 换成 `-`（git ref 不允许这两个字符）；Orca 落盘时会再把 🐎 转写成 `horse`，实际分支为 `refs/heads/wupengbo125/horse-codebuddy-<标题>`
- 无 `-i` 时 `ISSUE_TITLE` 为空，标题/分支退化为 `🐎-agent-`，属既有边界，未处理

## 三条新行为（用户后续追加）
- 无 `-i` 时自动 `gh issue list --state open --limit 1 --json number --jq '.[0].number // empty'` 取最新 open issue；同时删除了原来的「必须提供 -i 或 -p」校验
- 参赛数为 1 时 `horse=""`，标题与分支都不带 🐎；>=2 才带。判断用的是填充默认 agent 之后的 `${#AGENTS[@]}`
- 子命令 `race set-default-agent <agent>` 写 `~/.config/race/default-agent`；不带 `-a` 时读它，两者都没有才报错

## 附：踩到的脚本陷阱
- `set -euo pipefail` 下 `cmd | grep -q` 恒为假阴性
- `orca terminal wait --for tui-idle` 超时/未就绪返回非 0，会被 `set -e` 掐断后续命令
- `orca terminal read` 默认返回时序流，要看 TUI 实际渲染需加 `--screen`
