# install.sh 菜单重构 + 钩子安装修复

会话：01a0c463-0b60-745e-b7c0-4616b5c7f694
日期：2026-09-21

## 背景诉求
用户反馈 install.sh 交互流程有毛病：第一步先选技能、第二步才选操作，导致"只想装记忆钩子"也被迫先勾技能；且操作菜单顺序与文案不符合预期。

## 关键决策（均为用户明确要求）
1. **记忆钩子改为第一步的勾选项**（不是第二步的操作）：勾上后无论第二步选安装还是卸载，都执行钩子安装；全选同样生效。钩子与技能流程解耦，不参与 `processed` 计数，也不触发 `one-context.md` 初始化。
2. **删除两个"当前项目"操作**（安装到项目 / 卸载自项目）：只保留全局。连带删除全部 `scope` 管线——`apply_selection` 去掉 scope 参数、删除 project 分支、`OP_SCOPE`/`OP_SCOPE_LABEL`、`one-context.md` 初始化等死代码。
3. **操作菜单文案定为「安装 / 卸载」四字**，不加"到用户全局"等修饰。
4. `rule`（宪法规则）与 `gitignore`（忽略配置）本就无全局/项目之分，改为勾选即执行，不受 scope 影响。

## 钩子安装逻辑修复
`install_memory_hooks` 重写为纯增量、非破坏性：
- pre-commit 门禁装给所有项目仓；跳过记录型仓库（`one-hippocampus`/`one-life`/`one-llmwiki`）。
- post-commit（FTS 索引同步）+ `fts.py` 专属 `one-hippocampus`。
- **不再写任何 `rm` 清理逻辑**：一次性清理手动做一次即可，不落进常驻脚本。

## 涉及产物
- `install.sh`（唯一改动文件）
- 手动清理：6 个仓库残留的旧"记忆提醒"版 post-commit（chanlun-108-wiki / dotfiles / ebbiii / freeme / pixelbloom / qmt-parser）

## 追加：pre-commit 自动拉海马仓
原设计「写入方须先 `git pull` 最新再校验」为手动拉，实际导致远端直写后本地 clone 落后、被门禁误拒（本次提交 install.sh 时就卡了一次）。

改为钩子自动拉（带 15s 超时）：
- `one-memory/hooks/pre-commit`：校验前 `timeout 15 git -C <hippo> pull --ff-only --quiet`；rc=124 直接报"超时"并拒绝，其他失败打印警告后改用本地校验；报错文案去掉「并 git pull 最新」。
- `one-memory/BLUEPRINT.md`：规则改为「钩子会自动 `git pull` 最新再校验」。
- 用 `install-hook.sh` 重装到 7 个仓库。

设计取舍：`git pull` 同步阻塞，拉慢不会误判；超时只用于把"无限卡死"变成"快速失败并明确报超时"，好让 AI 汇报、用户修网络后重试。跳过拉取无法继续（本地落后必被拒）。

## 过程教训
用户给的字面文案必须原样落地，禁止自行扩写；一次性清理不得写进常驻代码。
