## 背景与诉求
用户需要一种在 Orca 环境下的多 Agent 赛马机制（Orca Race 模式）：
能够将同一个 GitHub Issue 任务或自定义 Prompt 同时分发给多个不同的 Agent（如 Codex、Claude、OMP、CodeBuddy 等），并且支持针对不同 Agent 单独指定模型。每个 Agent 在独立隔离的 Git Worktree 中并发运行并互相独立，避免代码修改冲突。

## 调研事实与关键决策
1. **官方 Orca 约束核实**：
   - 官方内置 `orchestration` 技能只是一个 discovery stub，并不包含底层真实 agent 白名单与适配方案。
   - Orca 源码内部硬编码了内置 TUI Agent 列表（`claude`, `codex`, `omp`, `opencode`, `pi`, `antigravity`, `gemini` 等）。
   - 腾讯 CodeBuddy 安装在 `~/.local/share/prime-agent-node/current/bin/codebuddy`，不在官方 TUI 白名单内。
   - 字节 TRAE 桌面版无独立命令行 CLI，不可行。
2. **架构设计决策**：
   - 技能命名对齐体系：`one-orca-race`。
   - 脚本 `race.py` 负责抓取 GitHub Issue（调用 `gh issue view`）、组装 Prompt、解析 `agent[:model[:effort]]` 格式参数。
   - 针对原生与非原生 Agent 进行统一封装：
     - 原生 Agent（无特殊模型时）：通过 `orca worktree create --agent <id> --prompt <text>` 一步拉起。
     - 原生 Agent 带 Model 或非原生 Agent（如 CodeBuddy）：先用 `orca worktree create` 创建独立分支 worktree，再用 `orca terminal create --command ...` 创建终端并通过 `orca terminal send` 注入 Prompt。
   - 支持 `--dry-run` 空跑模式。
