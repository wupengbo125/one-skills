# Task: one-todo 提示词模板改名与自动评审闭环修正

- **会话ID**: `31d251ba-0bb7-47c1-a73e-b2373dfb2df3`
- **日期**: 2026-09-27
- **主题**: 模板名字统一为「XX向导词」、需求框统称为「需求详情」、修自动评审重复触发与通过后的回评

## 1. 背景
同一份东西在界面、文件名、报错、说明文档里有四五套叫法（提示词模板 / 前导词 / 开场指令 / 发送提示词 / 评审基准 / 本次需求），且评审弹层写着一句「请在『审阅配置』页发起评审」——根本没有这个页面。另外自动评审会重复拉起：干活马只是说话等待用户暗号、没有任何代码改动时，回合结束也触发一轮评审。

## 2. 名字统一（四份模板 + 一个需求框）
1. **开场向导词**：任务开跑前固定拼在提示词前面的那段（原「开场指令」）。
2. **赛马向导词**：多匹马评审那份（原「评审-多马」）。
3. **评审向导词**：一匹马评审那份（原「评审-单马」）。
4. **整改向导词**：把评审意见发回干活马时夹在前面的那句（原「下发改进意见 / 前导词」）。
   - 用户随后亲手在这份向导词里写入了暗号 `aaa`，让干活马收到自动授权继续改，不再停下来问人。
5. **需求详情**：评审弹层里装需求内容的那个框（界面标题曾叫「评审基准」、说明文档曾叫「本次需求」，现在统一）。

文件名、保存后的提示、后台校验报错、折叠框标题、说明文档全部对齐；界面标题不再挂「（多匹马）」「（一匹马）」这类尾巴。
「下发改进意见 ↩」按钮与动作提示保留——那是动作，不是模板名。

## 3. 评审结论那块
- 删掉错的那句「请在『审阅配置』页发起评审」，换成「请先进行评审。」；评审员正在跑时的提示保持原样。
- 评审结论区改成**恒显示**：有评审员发回来的内容就装进去，没有时框照样在、里面显示「（空）」；展开收起行为没动。

## 4. 自动评审闭环（按通过/不通过分流）
| 评审结论 | 行为 |
| :--- | :--- |
| 通过，无建议 | 什么都不发，自动停 |
| 通过，有建议 | 把建议发回干活马，发完就把自动轮次停掉，它改完不再回评 |
| 不通过 | 建议发回干活马，改完立刻再拉下一轮 |

## 5. 空回合不拉评审
干活马回合结束时，翻 Paseo 在这一回合事件里带的**做事流水**，看有没有写/改文件类的工具调用：
- 认出是写、改文件的工具 → 动过代码，照评
- 认出是纯查看的工具（读文件、搜索、列目录、待办、联网查） → 没动，不触发
- 认不出是什么工具 → 按"动过"算，宁可多评一次也不漏

**为什么不用 git 对比**：Paseo 的 `agent.turn_ended` 事件自带 `timeline`，每一条工具调用都有工具名和是否成功，不用插件自己去 fork git 做快照比对。

## 6. 手工也能随时再来一轮
手动点「发起单马审核」这条路径根本不看自动轮数开关，只看评审是不是正在跑；想恢复自动，把弹层里「自动评审轮数」重新点一下数字即可（会把已用轮数清零）。唯一的坑：上一轮评审会话还活着时点发起会变成"接茬继续评"，要全新一轮得先归档那个评审会话。
