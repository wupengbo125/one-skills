# orca-20260918-a1 — one-orca-race 脚本 shell 化与命令暴露

## 背景诉求
用户有一个 Orca 多 Agent 赛马技能 `one-orca-race`（`scripts/race.py`），觉得 Python 版运行麻烦，问能否改成 shell；随后明确选择「完整移植」，并要求把命令做成全局可用（环境变量或别名二选一）。

## 关键决策
- **移植 = 替换**：用户明确否定"Python 版与 shell 版并存"，最终 `race.py` 删除，只留 `scripts/race`。
- **选 PATH 不选 alias**：别名只在交互式 shell 生效，脚本/子 shell/其他工具调不到。
- **暴露方式只做配置**：把脚本目录加进 PATH，不在 `dotfiles/bin/` 建转发脚本（先做错了一版 `bin/race` exec 转发，被要求删除）。

## 代码结论
- `one-skills/one-orca-race/scripts/race`（bash，可执行）：`getopts` 风格解析 `-a/-i/-p/-r/-b/--dry-run`；`gh issue view --json` + `jq` 抓 Issue 组 prompt；原生 agent 用 `orca worktree create --agent X --prompt`，非原生/带模型用 `worktree create` + `terminal create` + 后台 `sleep 2 && terminal send`。
- handle 提取兼容三种返回：`.result.agentTerminalHandle // .result.startupTerminal.handle // .result.handle`。
- `dotfiles/rc/bash/path` 加 `path_add "$HOME/onespace/github/one-skills/one-orca-race/scripts"`。

## 踩坑
- `parse_spec` 若写成 `agent="$(parse_spec "$raw")"` 会在子 shell 执行，全局变量 `A_MODEL/A_EFFORT` 丢失，dry-run 显示 model=默认。改为直接调用 `parse_spec` + 读 `$AGENT_ID`。

## 涉及产物
- `one-skills/one-orca-race/scripts/race`（新，替 race.py）
- `one-skills/one-orca-race/SKILL.md`（命令改为 `race`）
- `dotfiles/rc/bash/path`（新增一行）
