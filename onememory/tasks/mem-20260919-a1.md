# mem-20260919-a1 海马记忆仓摘要等号门禁

## 背景
pre-commit 只校验本仓库有无 `onememory/`，管不到海马记忆仓是否真落盘，Agent 时有漏记。

## 权衡
- 方案「查海马本地 status」直接失效：海马写入是远端直写（one-ghfile），本地 clone 永远干净
- 更硬的坑是时序：原 SOP 提交在前、写海马在后，pre-commit 时必然还没写，会 100% 误杀
- 结论：SOP 调序（先远端落海马再提交）+ pre-commit 用 gh api 拉远端当日文件比对

## 实现
- `references/write-memory.md`：Step3/Step4 互换，加「等号铁律」（时间戳与项目路径之后逐字照抄 timeline 行）
- `hooks/pre-commit`：有实质改动时，取 timeline 末行与远端当日文件最后一个 `[~/项目路径]` 行，各自 sed 去前缀后整行等值比对，缺失或不一致拒绝提交
- key 用项目路径而非会话 ID，不依赖任何 Agent 专有环境变量

## 补充（17:05）
钩子分发排除记录型仓库：海马仓 / one-life / one-llmwiki 本身就是记忆载体，不装沉淀门禁，已装的由 install-hook.sh 自动清理。

## 补充（18:57）
门禁恢复「全部拦截」：删掉 9-18 加的 AI 会话判定（CODEBUDDY_SESSION_ID/CLAUDE_SESSION_ID 探针），任何提交都走 onememory 门禁 + 海马等号校验；用户本人提交自行 --no-verify。海马偏好中「人工放行」那条同步订正。

## 验证
- 缺海马记录 → 拒绝提交 ✅
- 干净环境（无 session env）人工提交 → 放行 ✅
