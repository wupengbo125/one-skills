# one-todo 委员会模式（指定两匹马）

## 诉求
- 用户要把「委员会模式」接进待办：发起界面多一个模式按钮，打开后指定一个技能 + 两个成员（Agent/模型），
  全军出击只开一匹马，由它照技能派生两个成员。
- 关键澄清：**我们不自建委员会**，只复用现成的 `paseo-committee` 技能；要做的是把「用哪个技能、用哪两个 Provider」
  传下去，不让技能自己 `list_profiles` 挑。
- 模式三选一：普通 / 委员会 / 赛马。委员会只准一匹马，可 Local 可 Worktree，只有一个工作区，
  派生成员都落在它自己那个工作区里。

## 决策
- 委员会技能和两个成员写进那匹马的开场提示词（技能走 `[使用技能: …]` 前缀，成员单独一段），
  不做任何编排逻辑，纯粹传参。
- 模式锁只由「派过马」判定（有没有会话 / 工作区），不看委员会标记字段。
- 委员会标记只在**派马成功**时落库（对齐 raceMode）；启动失败不能把模式段锁死。
- 保存草稿记模式（可撤销），成员配置只在委员会模式下写；普通 / 赛马成功启动不落 false 噪声。
- 两个成员默认留空，必须显式选齐才让开跑（避免两人同源丢掉对比意义）。

## 评审三轮踩过的坑
1. 委员会标记进启动前的 update patch → 启动失败一次就永久锁死模式段。改：只随成功对象写。
2. 门控被 `committeeMembers !== undefined` 满足 → 光删 `input.committee` 那句不生效，patch 里的写入也得删。
3. 保存路径漏写 / 多写 committee 反复横跳：最终定为「保存记模式 + 执行只在委员会时留标记」，
   锁判定与标记解耦后两边互不干扰。

## 约束
- 需求外改动一律回滚（本次回滚了开场向导词里多加的一句）。
- 起手先记起点 commit；工作区有未提交改动要先报给用户裁决。
