# 会话 829e4c9b-ed47-4646-9d76-946d849182ae

## 主题：one-todo 三点菜单点击外部不关闭

背景诉求：待办卡片右上角「⋮」弹出的菜单，只有再点一次「⋮」才关；点页面其它任何地方（别的卡片、空白、滚动、切筛选）菜单一直挂着。用户要业界常规做法——点菜单外部任意区域即关。

### 排查与结论（委员会两匹马）

用 paseo-committee 开了两匹（codebuddy-code/deepseek-v4.1-flash、opencode/mimo-v2.6-flash-free）。opencode 那匹连续两次报 `unknown certificate verification error`（免费模型服务端 TLS 连不上），用户决定不换人，本轮只有一匹马出结论。

根因：不是冒泡/pointerEvents 写错，是**缺功能**。菜单开关是个孤立状态，全 client 只有 6 处能改（⋮ 自身 + 4 个菜单项），点别处时被点的元素自己消化点击，没有任何"外部按下"的判定层；滚动也没有监听。

业界三条路：全屏透明背板（跨端稳、代价是第一次点击被背板吃掉）、全局捕获指针监听（能透传点击，只有浏览器端有）、系统原生菜单（天然点外即关，但样式不可定制、长按交互会丢）。Paseo 插件 SDK 没有现成的"点外部关闭/Popover"能力；宿主自带的 Modal 是带标题栏的整屏 sheet，蹭不上。宿主的弹层用的是"拿触发元素 measureInWindow 现量现算"这条路。

### 实现（背板方案）

- 菜单搬出卡片，和页面级弹窗放同一层（放在列表滚动区之后）；打开时铺一层透明背板接住"点外面"，菜单压在背板之上。
- 位置：打开那一刻对三点按钮与整个面板各做一次 measureInWindow，换算成面板内坐标（滚动偏移天然含在里面）。
- 关闭入口：点背板 / 电脑端 Esc（仅 web，手机端没有键盘）/ 点菜单项做完自动关 / 滚动列表 / 切筛选（含仓库筛选）/ 打开编辑窗 / 现有统一关闭浮层出口。
- 顺手删掉"菜单打开时把卡片抬高一档"的 zIndex（菜单搬走后成了死代码）。

Esc 走 client/web.ts 新增的 `onEscape`，沿用该文件"自己 declare window"的写法（插件不引 DOM lib）。

### 关键坑：插件源码改了不自动生效

改完 grep 类型检查都过，用户测仍毫无效果。根因是 **Paseo 插件直读源码、不热更**，跑的仍是 17:50 装载的那份老代码，而改动是 18:16 才落盘。`paseo plugin reload one-todo` 后装载时间 18:24，才算生效。

这条本已写在 `paseo-plugins/one-todo/one-context.md` 和仓库根 `one-context.md`，我进去没读；后来去低优先级的 `onememory/rules.md` 里找，被用户斥"高优先级的不看、去低级的地方写"。用户拍板把 rules.md 里那条与 one-context.md 重复的条目（"改 Paseo 插件源码后必须重载插件再自测/交付"）删掉。
