# one-paseo-review

会话：3cec82f8-938f-4cb8-843c-7a529b1434e8

## 背景诉求

用户要一个能调用**别家厂商** coding agent 做 code review 的技能。现有 code-review 技能（Superpowers 的 `requesting-code-review`）只能调本会话的 sub agent，必然同一家模型，视角重叠。

## 关键决策

- **评审员默认写死 `codebuddy-code/space-bunny`**。用户不指定就用它，不问不解释。用户嫌每次指定 provider 太费力，要一个默认值兜底。
- **技能保持 `disable-model-invocation: true`**。用户打名字调它就算自动发起 —— 不需要 model-invoked。原先我误以为"自动"必须让模型自己触发，用户纠正：写上名字就等于他调了。
- **评审词汇一律取自待办插件 `paseo-plugins/one-todo`，不取 Superpowers**。用户明确要求参考插件里那些词。采用的：评审员、目标只读、等号审查（总超出需求 / 是否少需求）、结论首行「结论: 通过」或「结论: 不通过」+ 问题清单（标阻塞）、起点提交 ID 决定本轮范围（含未提交）。
- **调用形态照 `paseo-committee`**：先读 paseo 技能 → `create_agent` 发出 → 开`notifyOnFinish` → 不轮询等通知。
- **`one-paseo-review` 自身不绑 `one-audit-plan`**。需求收敛由 `one-implement` 负责，做成链路：`one-plan` 出计划 → aaa 落盘 → `one-audit-plan` 收敛成一份全量需求 → `one-paseo-review` 派评审员。
- **`one-audit-plan` 就是用户记忆里"把v1/v2/v3 收敛成一份统一需求去审"的技能**，与待办插件里赛马马自己写的 `audit-list.md` 同源。

## 踩的坑

- **待办插件里已有自动评审（`autoReview` / `autoStartReview` / `autoAdvanceReview`）**，弹层有「自动评审轮数」控件。但那是手动点开后才循环跑，触发是手动开的。我一度误判成"功能不存在"，被用户纠正：他要的是**这个会话干完活自己能触发**。
- **装技能时别只装一个 agent**。我凭"用户在 CodeBuddy 里干活"就只装 codebuddy，被骂。脚本支持四个技能位：`agents`、`claude`、`codebuddy`、`trae-cn`，应该全装。安装是常识动作，不该问用户"装不装"。
