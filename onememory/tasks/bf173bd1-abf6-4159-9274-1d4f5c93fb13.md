## 诉求
用户在 one-todo 里点「开炮」报错 `Workspace has no available directory.`，把这句报错存成待办让我修。起因是「one todo 架构优化」那条待办（seq 12，source=issue，绑 wupengbo125/one-skills#7）。

## 排查
- 该待办绑定的 workspace `wks_f56414bee8567f7a` 已于 11:25:39 归档；11:33 再开炮就报这个错。
- daemon 日志里没有这句文案 → 报错来自插件/客户端侧校验，不是 daemon。
- 插件源码：`paseo-plugins/one-todo`（`paseo plugin ls` 的 SOURCE）。

## 根因
`server/todo.ts` 的 handleStartTodo 只要待办存了 `workspaceId` 就无条件 `workspaces.ref(id).agents.create(...)`，从不校验该 workspace 是否仍 active。归档后 ref 指向失效对象即报错。

## 代码结论
- `workspaces.list()` 只返回 active（63 条历史里带 archivedAt 的不返回）→ 用它做有效性校验。
- 生命周期事件 `workspace.archived` 的 `event.workspace` 带 `id / projectId / cwd / archivedAt`，可在归档瞬间把项目信息补记到待办上，供日后重建。
- 待办 store 有内存 cache（`server/store.ts`），插件运行时直接改 `~/.paseo/plugin-data/one-todo/todos.json` 会被 cache 覆盖 → 修数据必须走插件自己的写入，不能手改文件。

## 改动
1. 新增 `workspaceIsActive` / `resolveProjectPath` 两个 helper。
2. 开跑前校验 workspaceId，失效则丢弃并按 `projectPath`（缺失时用 projectId 反查项目根路径）重建 workspace，新 id 写回待办。
3. 归档事件里 `stashWorkspaceProject`：把 workspace 的 projectId 补记到引用它的待办（仅补空缺的）。
4. 失效且确实没有项目信息时，返回中文错误「该任务的工作目录已失效，请重新选择项目目录」。

## 遗留
seq 12 那条待办的归档发生在本次修复之前，项目信息没被记下来，需要用户在 UI 上重选一次项目目录；之后归档的都会自动记下。
