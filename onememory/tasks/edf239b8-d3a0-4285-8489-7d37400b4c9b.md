# Task: one-todo 待办自动审核机制重构

- **会话ID**: `edf239b8-d3a0-4285-8489-7d37400b4c9b`
- **日期**: 2026-09-27
- **主题**: 修复待办自动跑审核机制与归档倒挂问题

## 1. 背景与死穴排查
用户提问待办自动原理以及自动审核如何获知干活马跑完。经排查代码发现原逻辑存在严重倒挂：
1. `agent.turn_ended` 中如果干活马正常完成回合（`completed`），代码直接 `return`，不触发审核。
2. 原逻辑要求用户必须手动点「归档」（`agent.archived`）才判定待办 `done` 并触发 `autoStartReview`。
3. 但「归档」意味着会话已关闭销毁；评审员审完如果有建议或不通过，调用 `handleReviewSend()` 根本无法发回给已归档的会话，造成逻辑死锁。

## 2. 关键决策
1. **解除归档触发强绑定**：归档回归本质（仅作为删除清理与结项），不再作为启动自动审核的开关。
2. **回合结束直接触发审核**：干活马一轮结束（`agent.turn_ended` 且 `completed`），只要开启了自动审核，直接调用 `autoStartReview()`，干活马会话保持在线活着。
3. **闭环发回修改**：评审不通过或有建议时，通过 `handleReviewSend()` 发回给仍然存活的干活马；干活马修改完回合再次结束，自动触发下一轮评审。
4. **多马完全解耦**：多马场景仅负责横向比对选出胜者，未选出胜者前不自动拉起单马审核；一旦确定胜者，自动收敛为对胜者单马的审核循环。
5. **通过后收工**：单马评审通过且无建议时，将待办标记为 `done` 并停止自动轮次。

# Task: one-todo 提示词模板白盒化与待办跳转继承

- **会话ID**: `edf239b8-d3a0-4285-8489-7d37400b4c9b`
- **日期**: 2026-09-27
- **主题**: 提示词模板落盘为插件资产，去除黑盒拼装；待办支持编号继承会话

## 1. 背景
待办插件里四处提示词名字混乱、部分提示词写死在后台不可见不可改，需求文档存在中文目录不便引用。

## 2. 关键决策
1. **模板落盘**：开场、评审（单马/多马）、下发改进意见四份提示词统一落在插件 `prompts/` 目录，随插件仓库走，界面可编辑/保存/预览。
2. **去黑盒**：彻底删除后台写死的开场提示词拼装代码，改为读取 `开场指令.md`，支持 `{{docPath}}` 与 `{{id}}` 变量替换。
3. **改名对齐**：评审意见前置话语令由「发送提示词」改名「下发改进意见」，文件名与界面折叠框、按钮名统一。
4. **需求目录英文化**：需求文档存储目录由中文改 `requirements`，保留旧路径兼容读取。
5. **待办跳转**：进行中/失败待办的跳转箭头常驻；未绑会话时弹窗输入待办编号即可继承其会话与工作区并跳转。

## 3. 涉及文件
- `paseo-plugins/one-todo/prompts/`：新增 `开场指令.md`，`发送提示词.md` 改名 `下发改进意见.md`。
- `paseo-plugins/one-todo/server/review.ts`：模板表统一管理（multi/single/send/initial）、读写与校验。
- `paseo-plugins/one-todo/server/executor.ts`：开场指令变量替换拼接。
- `paseo-plugins/one-todo/server/taskdoc.ts`：需求文档目录改 `requirements` 并兼容旧路径。
- `paseo-plugins/one-todo/client/todo.tsx`：三个模板编辑折叠框、跳转编号继承弹窗。

## 4. 遗留
- README 仍有一处旧名「发送提示词.md」未同步。
- 四份模板命名尚未统一前缀（开场指令/评审/下发改进意见叫法混杂）。
