# Task: one-todo 待办自动审核机制重构

- **会话ID**: `edf239b8-d3a0-4285-8489-7d37400b4c9b`
- **日期**: 2026-09-27
- **主题**: 修复待办自动跑审核机制与归档倒挂问题

## 1. 背景与死穴排查
用户提问待办自动原理以及自动审核如何获知干活马跑完。经排查代码发现原逻辑存在严重倒挂：
1. `agent.turn_ended` 中如果干活马正常完成回合（`completed`），代码直接 `return`，不触发审核。
2. 原逻辑要求用户必须手动点「归档」（`agent.archived`）才判定待办 `done` 并触发 `autoStartReview`。
3. 但「归档」意味着会话已关闭销毁；评审员审完如果有建议或不通过，调用 `handleReviewSend()` 根本无法发回给已归档的会话，造成逻辑死锁。

## 2. 关键决策
1. **解除归档触发强绑定**：归档回归本质（仅作为删除清理与结项），不再作为启动自动审核的开关。
2. **回合结束直接触发审核**：干活马一轮结束（`agent.turn_ended` 且 `completed`），只要开启了自动审核，直接调用 `autoStartReview()`，干活马会话保持在线活着。
3. **闭环发回修改**：评审不通过或有建议时，通过 `handleReviewSend()` 发回给仍然存活的干活马；干活马修改完回合再次结束，自动触发下一轮评审。
4. **多马完全解耦**：多马场景仅负责横向比对选出胜者，未选出胜者前不自动拉起单马审核；一旦确定胜者，自动收敛为对胜者单马的审核循环。
5. **通过后收工**：单马评审通过且无建议时，将待办标记为 `done` 并停止自动轮次。

## 3. 涉及文件
- `paseo-plugins/one-todo/server/review.ts`：导出 `autoOn`，放开 `autoStartReview` 状态门禁，审核通过无建议时自动更新待办为 `done`。
- `paseo-plugins/one-todo/index.server.ts`：在 `agent.turn_ended` 中对干活马正常完成直接触发 `autoStartReview`；移除 `agent.archived` 与 `workspace.archived` 中的触发逻辑。
