## 背景诉求
用户一句话：待办插件的委员会模式不要用黑盒提示词告诉 Agent 用什么技能，要"主动从那个技能框里把技能选好"，这样他在界面上能感知用了哪个 Skill、指定了哪个 Provider。原实现在 executor 里写死 `paseo-committee` 并写死一段台词，用户称之为"黑活"。

## 关键决策
- 技能不再代码硬塞：点「委员会」时插件把 paseo-committee 勾进界面「使用技能」框（看得见、能改、能删），派马只按技能框里选的下发。
- 台词不进代码：委员会成员那句移到现成的「委员会开场向导词」，新增 `{{members}}` 空位，派马时把两个成员的 Provider / 模型填进去。
- 不替用户挑：`COMMITTEE_SKILL` 只在 shared 定义一处；技能列表里没有就不自动勾（老单补勾同一把尺子）。
- 不发明东西：只叫技能、只替它挑两个 Provider；技能自己建两个 Agent，建在哪怎么收敛全听它的——原台词里"不要另开工作区""不要让技能自己挑成员"这类我们自己加的规矩全删。

## 评审两轮的整改
- 第一轮两条阻塞：
  - 成员静默丢失：默认委员会开场向导词没有 `{{members}}`，且已存在的文件不会重播种 → 默认那份与仓库那份都带上这句话，派马时若向导词缺 `{{members}}` 直接拦下报错，不静默丢成员。
  - 老委员会单被新校验卡死：以前技能是服务端硬塞不落库，`committeeMode` 的老单技能框里没有它，而模式按钮 modeLocked 禁用无法补 → 开弹层时补勾。
- 第二轮三条建议（都真，全改）：列表没加载仍会勾 → 只认列表；老单补勾不校验安装 → 与点按钮同一把尺子；已在委员会里再点按钮会把用户删掉的勾回来 → 只在从非委员会切进来时勾。

## 代码结论
- shared/todo.ts：`COMMITTEE_SKILL` 单点定义。
- client/todo.tsx：委员会按钮自动勾（只在列表里有 + 非委员会态）、dropAutoCommitteeSkill 切走只撤自己勾的、openDetail 老单补勾。
- server/executor.ts：删写死技能名与整段台词；委员会拦"技能框空"与"向导词缺 {{members}}"；formatInitialPrompt 多收 members 替换 `{{members}}`。
- server/review.ts + prompts/委员会开场向导词.md：默认那份带 `{{members}}` 那句。
