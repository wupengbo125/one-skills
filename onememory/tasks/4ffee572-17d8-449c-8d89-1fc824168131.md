## 背景诉求

委员会模式下那两位委员 Provider，每次新建任务都是空的，用户每次都要重选。要求像上面那个单 Provider 一样"有个记录位"：

- 保存一张委员会单时，当前两位委员既落在这张单自己身上，也更新一份全局默认。
- 新建委员会单时，两个框默认带出全局默认那两位。
- 以后哪张单再保存，全局默认就换成那张单当前的两位；老单自己那份不动，打开老单仍显示它自己存的两位。

## 排查过程（关键教训）

第一轮改完（保存时写全局、新建时读全局）后用户反馈"点开还是空"。

根因两条：

1. **改完没重载插件**。Paseo 插件直读 `paseo-plugins/<id>` 源码，不自动热更；必须 `paseo plugin reload one-todo` 才生效。改代码时最后一次 reload 停在当日 17:11，而改动在其后，用户测的仍是旧界面。查 `paseo plugin logs one-todo`，最新 `Plugin ready` 时间戳能对出来。
2. **历史数据没有全局记录**。旧的保存动作跑在旧代码下，`preferences.json` 里没有 `lastCommitteeMembers`，所以新建单仍空。光靠"以后保存才记"救不了已有单。

## 关键决策

- 全局默认存进插件本地偏好（`~/.paseo/plugin-data/one-todo/preferences.json`）的 `lastCommitteeMembers`，与已有 `lastProvider/lastModel` 同处。
- 写入时机＝保存委员会单（新增/编辑两条保存路径），不是"点选即记"，贴合用户"保存之后全局就被更新"的原话。
- 兜底：全局没记过时，客户端从现有待办里取最近一张"委员会模式且两位齐全"的单，用它的两位当默认。这样老单能直接带出来。

## 涉及产物

- `paseo-plugins/one-todo/shared/todo.ts`：preferencesSchema 加 `lastCommitteeMembers`。
- `paseo-plugins/one-todo/server/todo.ts`：handleAddTodo / handleUpdateTodo 落盘委员时同步写全局默认。
- `paseo-plugins/one-todo/client/model.ts`：新增 `lastCommitteePair()` 兜底取最近委员会单。
- `paseo-plugins/one-todo/client/todo.tsx`：openDetail 两委员默认值＝老单自存 > 全局默认 > 兜底 > 留空。
- `paseo plugin reload one-todo`（插件 reload，直读源码不热更）。
