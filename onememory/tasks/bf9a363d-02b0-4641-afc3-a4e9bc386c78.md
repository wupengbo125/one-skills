# 待办插件普通模式新增向导词失败问题修复

- 会话ID: bf9a363d-02b0-4641-afc3-a4e9bc386c78
- 时间: 2026-10-05 10:14

## 背景诉求
待办插件在普通模式下新增前导词/向导词时，没有新增成功。

## 排查过程与根因
1. `client/todo.tsx` 中 `initialSaveM` 的 `mutationFn` 在新增前导词未给 `newName` 时，兜底用了 `initialTitle.trim()`（旧前导词名称）。后端 `writeInitialPromptRaw` 将其作为重命名覆盖了旧文件，新文件未生成。
2. `validInitialName` 校验新名字必须已存在于 `initialListQ` 缓存中，刚创建未拉取完时被当成非法直接弹回第一项。
3. `initialSaveM.onSuccess` 缺少对 `todo-initial-prompt` 缓存的失效刷新。

## 解决决策
1. `initialSaveM.mutationFn` 去除 `initialTitle.trim()` 兜底，保持 `newName` 为 `vars.newName`。
2. `activeInitialName` 优先直接使用 `run?.initialPromptName`。
3. `initialSaveM.onSuccess` 补充刷新 `todo-initial-prompt` 缓存。
4. 运行 `npm run typecheck` 验证类型并通过 `paseo plugin reload one-todo` 重载插件。
