# 极简实现流程 (One Implement)

核心原则：平铺计划、最小化实现、严防多改。能简单就不要多写。

---

## 流程

### 1. 平铺计划（动手前）
列出一行一行的平铺 plan（严禁嵌套复杂大纲），明确每步具体改动。向用户确认后开工。

### 2. 最小化最简单实现
- 严格以需求为边界，只改需求相关内容。
- 绝不顺手重构，绝不添加多余抽象，绝不改无关文件。

能简单就不要多写，以最小代码量达成目标。

### 3. 认真设计

在需求边界内把设计想透：选最合适的结构、最简洁的实现。这一步是"想清楚"，不是"多写"——不加需求外的代码、抽象、设计模式。

### 4. 等号审查
对照用户原始需求与 `git diff HEAD`：
- 改多了？（有无未要求的改动、多余抽象）
- 改少了？（需求是否遗漏）
- 改偏了？（是否符合预期）

改动必须与需求严格画等号。
