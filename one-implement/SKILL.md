# Implement Router & Coding Constitution (实施路由器与编码宪法)

根据当前需求、对话上下文或 PRD 文档，在实施编写代码前，严格遵循编码宪法，判定任务分支并执行。

## 流程

### Step 1: 判定任务类型 (Task Classification)

分析当前实施目标的本质属于“重构”还是“新实施”：

- **分支 A: 重构类型 (Refactor)**
  - **触发条件**：涉及已有代码的重构、提取、逻辑合并、模块拆分、代码迁移或方法重构。
  - **路由操作**：严格按 physical copy 物理复制（cp/mv/cat/脚本）与微创修改原则，非修改区 100% 绝对禁触，严禁凭记忆重新敲打。

- **分支 B: 新功能实施类型 (Minimal Implement)**
  - **触发条件**：涉及 0 到 1 的全新功能落地、新模块/组件/接口添加或补全需求。
  - **路由操作**：严格按极简交付与范围控制原则进行精准修改与测试验证，用最少的代码解决问题。

### Step 2: 实施核心规范 (Coding Constitution)

1. **动笔前先思考**：明确假设，不盲目假设，不隐瞒困惑；如果有更简单的方法，直接说明。
2. **至简至上**：
   - 绝不添加超出需求范围的功能，能用一行不用两行。
   - 拒绝为确定性事物写防御性代码。
   - 拒绝写兜底方案（A不行就报错修A，不造B来兜底）。
3. **精准微创**：
   - 涉及已有代码必须物理复制/剪贴，非修改区禁止改动。
   - 只清理自己改动带来的孤立引用，不擅自删除原本就有的死代码。
4. **路径与环境变量约束**：
   - 凡是已有环境变量（如 `$github_dir`、`$onespace_dir`），代码和配置中必须直接引用环境变量，严禁硬编码绝对路径或多层手动拼接。
5. **工程标准**：
   - Python 优先使用 UV，命令行与文档使用 `uv run` 代替 `python`。
   - 文档统一全小写 `readme.md`，严禁使用 `README.md`。
   - 禁止使用系统的 `/tmp` 目录，需在项目内创建临时目录并在用完后删除。
   - 子项目采用标准三件套结构（`<script.py>` + `config.yaml` + `readme.md`）。

### Step 3: 验证与交付

1. 运行测试套件与验证命令，确保功能通过。
2. 汇报修改点与验证结果。
