# 自动记忆指南 (Auto Memory Reference)

> AI 在日常会话中的自主增量记录行为准则。
> **核心逻辑**：一个话题对应 `recent.md` 中的一条记录与 `memory/` 中的一个文件。会话推进中产生实质性改动时，由 AI 顺手追加更新，不依赖手动触发。

---

## 触发时机与增量维护

AI 在会话中观察到**实质性变更**（修改了代码/配置、做出了关键决策、排查了重大 Bug）时自主执行：

1. **首次产生实质改动**：
   - 检查 `$github_dir/one-hippocampus/memory/` 是否已存在今天同话题的文件。
   - 若不存在：创建 `memory/<YYYY-MM-DD_话题名称>.md`。
   - **调用 CLI 打卡与置顶**：
     ```bash
     free-me recent "<话题名称>" "memory/<YYYY-MM-DD_话题名称>.md"
     ```
     `free-me recent` 会自动将该记录置于 `recent.md` 表格首行、执行双阈值淘汰，并同步索引。
   - 若已存在：直接复用，准备追加。

2. **阶段性推进与增量追加**：
   - 不需要每次微调都记，在完成一个阶段性目标或改动方向发生转折时顺手记一笔。
   - **向同一个文件追加**：记录刚才改了什么、为什么改、遇到了什么坑、当前状态如何（保留演进过程，不全量推倒重写）。
   - **刷新流水与同步索引**：
     ```bash
     free-me recent "<话题名称>" "memory/<YYYY-MM-DD_话题名称>.md"
     free-me sync "memory/<YYYY-MM-DD_话题名称>.md"
     ```

3. **静态事实同步**：
   - 若过程中确认了新的不变事实（端口、服务、别名、硬件），顺手更新 `system/profile.md` 或 `system/aliases.md`，并执行 `free-me sync`。

---

## 什么时候不记

- 日常闲聊、简单问答、无实质代码/配置改动或架构决策的常规查阅。
- **宁缺毋滥**：不确定值不值得记，就不记。

---

## 与手工记忆的关系

- **自动记忆是主航道**：会话进行中增量沉淀，绝大部分记忆在此阶段已完成闭环。
- **手工记忆是兜底**：若自动记忆已完整记录，用户触发“收工”或“超级我”时仅需极简确认；若会话中未触发自动记录，手工记忆做最后全量兜底。两者互不冲突。
