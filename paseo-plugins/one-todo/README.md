# one-todo

Paseo 的待办插件：先把任务记下来，点「全军出击」才真的开 Agent 会话去跑。

## 基本用法

- 侧栏「待办」进入，点「添加」新建。
- 填标题（必填）、内容（要做的事 / 验收标准）。
- 选在哪跑：项目（默认 Local，也可切 Worktree），可另选 Workspace。
- 放马：选一个或多个 Provider / Model。多个 = 赛马并行。
- **长按**「全军出击」1 秒开始。

## 不点不知道的操作

- **长按 1 秒才开跑**：按住「全军出击」，按钮上的进度条填满才启动；中途松手＝取消，短按无效。
- **Local + 多个马 = 只建一个 worktree**：多个会话跑在同一个 worktree 里，不动你当前目录。
  （单个马仍在当前目录跑；Worktree 模式不变。）
- 点 `#序号` 徽标：把「请执行待办任务 #序号《标题》…」复制到剪贴板，并在 进行中 / 未开始 之间切换。
- 点标题：打开编辑。
- 点右侧 `⋮`：置顶 / 删除。
- **进行中**的任务，右边有个小箭头 `↗`：点一下直接跳到它的会话（多个 workspace 时跳第一个）。
- 失败的任务：「重连」回进行中；「重置」回未开始。
- 「已完成」只列当天的，隔天自动收走。
- GitHub Issue 页签：列出本地仓库的 open issue，点「存入待办」收进列表；点条目可配置后开跑。
- 「使用技能」可多选，开跑时自动在提示词前加 `[使用技能: …]`。

## 归档时会怎样

- 关掉 / 归档 Workspace，任务会自动标记完成。
- 某个 Workspace 开跑时若建过分支，**归档它就会删掉它对应的那条分支**（worktree 目录由 Paseo 自己删）。
  多个马各在一个 worktree 时，归档哪个就删哪个的分支，互不影响。
- **归档 = 你确认**：那条分支里没合并的改动会一起丢。留着用的那份请先合并 / 保好。

## 赛马仲裁

多马各在一个 worktree 跑完后，让一个**判官马**对比各候选谁干得更好。审是基本动作：单马就是审核，多马就是每匹各审一遍再挑胜者：

- 卡片右侧出现 `⚖`（跑过的任务就有，不只限多马；本地直接跑的也能审）。
- 弹层按候选数自动切模式：≥2 个是**仲裁**，1 个或本地目录是**审核**。
- 弹层里写**判定标准**（你写：从哪几个维度判），选**判官马**（独立的 Provider / Model）。判官提示词里一定带上任务原文（标题+内容），先看做没做对，再看代码好不好。
- 候选 worktree 目录自动解析：git worktree 按分支（权威）→ `worktrees.dir` → Paseo workspace 目录；目录没了会标红「已失效」。没有 worktree 就审项目目录本身。
- **开庭**＝另开一个判官 workspace + Agent：判官只读候选（`git -C <目录> status/diff`，要跑测试先导出 patch 到自己目录），把结论写进 `~/.paseo/plugin-data/one-todo/arbitrations/<待办id>.md`。
  - 仲裁结论四段：逐候选审核、胜者、综合报告（各家优点集中）、修改建议（在胜者那份上怎么改）。
  - 审核结论：首行「结论: 通过/不通过」+ 问题清单（阻塞/建议）。
- 结论在弹层里直接看，还能一键**发给干活的会话继续改**（审核发给那一匹，仲裁发给胜者那一匹）；改完点重新开庭/重新审核，形成循环。`跳判官 ↗` 进判官会话；归档 workspace 会顺手删判官分支。
- 仲裁中改不了状态：判官跑完只翻仲裁状态，不动待办本身的「进行中 / 已完成」。

## 数据在哪

`~/.paseo/plugin-data/one-todo/`：`todos.json`（待办）、`preferences.json`（上次的选择）、`arbitrations/`（各待办的仲裁结论）。
