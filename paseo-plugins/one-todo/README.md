# one-todo

Paseo 的待办插件：先把任务记下来，点「全军出击」才真的开 Agent 会话去跑。

## 基本用法

- 侧栏「待办」进入，点「添加」新建。
- 填标题（必填）、内容（要做的事 / 验收标准）。
- 选在哪跑：项目（默认 Local，也可切 Worktree），可另选 Workspace。
- 放马：选一个或多个 Provider / Model。多个 = 赛马并行。
- **长按**「全军出击」1 秒开始。

## 不点不知道的操作

- **长按 1 秒才开跑**：按住「全军出击」，按钮上的进度条填满才启动；中途松手＝取消，短按无效。
- **Local + 多个马 = 只建一个 worktree**：多个会话跑在同一个 worktree 里，不动你当前目录。
  （单个马仍在当前目录跑；Worktree 模式不变。）
- 点 `#序号` 徽标：把「请执行待办任务 #序号《标题》…」复制到剪贴板，并在 进行中 / 未开始 之间切换。
- 点标题：打开编辑。
- 点右侧 `⋮`：置顶 / 删除。
- **进行中**的任务，右边有个小箭头 `↗`：点一下直接跳到它的会话（多个 workspace 时跳第一个）。
- 失败的任务：「重连」回进行中；「重置」回未开始。
- 「已完成」只列当天的，隔天自动收走。
- GitHub Issue 页签：列出本地仓库的 open issue，点「存入待办」收进列表；点条目可配置后开跑。
- 「使用技能」可多选，开跑时自动在提示词前加 `[使用技能: …]`。

## 归档时会怎样

- 关掉 / 归档 Workspace，任务会自动标记完成。
- 某个 Workspace 开跑时若建过分支，**归档它就会删掉它对应的那条分支**（worktree 目录由 Paseo 自己删）。
  多个马各在一个 worktree 时，归档哪个就删哪个的分支，互不影响。
- **归档 = 你确认**：那条分支里没合并的改动会一起丢。留着用的那份请先合并 / 保好。

## 评审

多马各在一个 worktree 跑完后，派一个**评审员**去评：多匹马就挑出最好的一份（把各家好处揉成建议，指定一匹接着改），一匹马就直接给建议。两条路都是同一件事——评审。

- 卡片右侧出现 `⚖`（跑过的任务就有，不只限多马；本地直接跑的也能评）。
- 弹层按马匹数自动切模式，也能手动改：≥2 匹是**多匹马评审**，1 匹或本地目录是**一匹马评审**。
- **需求**：弹层里那个「本次需求」框决定评审员看到的需求。右侧两个按钮——`待办` 装待办里的标题+内容，`文档` 装那匹马写的需求清单（`audit-list.md`，放在系统临时目录、路径由插件在派马时指定）的内容；装进来的字可以自己删改。框空着点开始会提示「先选需求」。你手动提示词已并入这个框。
- 选**评审员**（独立的 Provider / Model）。
- 候选 worktree 目录自动解析：git worktree 按分支（权威）→ `worktrees.dir` → Paseo workspace 目录；目录没了会标红「已失效」。没有 worktree 就评项目目录本身。
- **开始评审**＝另开一个评审工作区 + Agent：评审员只读候选（只看不改，要跑测试先导出 patch 到自己目录），结果直接显示在弹层里。
  - 多匹马结果首行「胜者: <编号>」+ 逐匹点评 + 改进建议；一匹马结果首行「结论: 通过/不通过」+ 问题清单（阻塞/建议）。
- 弹层里能改**评审提示词模板**，两份文档各管一条路：
  - `paseo-plugins/one-todo/prompts/评审-多马.md`（多匹马）
  - `paseo-plugins/one-todo/prompts/评审-单马.md`（一匹马）
  - `paseo-plugins/one-todo/prompts/发送提示词.md`（发回给干活会话时，包在评审意见前面的那句话）
  这三份是插件资产，跟着插件仓库走（换机器也在）
  框里收起/预览/编辑三态，改完点保存模板；发起前改了没保存会先拦你。
- 结果在弹层里直接看，能一键**发给那匹马继续改**（多匹马发给胜者，一匹马发给它自己），也能**复制**出来自己粘；改完再评一次，形成循环。会话已结束或归档时发回会明确报错，不会往死会话里发。`跳评审员 ↗` 进评审会话；归档评审工作区只会删掉结果文件（评审只读，不开分支）。
- 评审中改不了状态：评审员跑完只翻评审状态，不动待办本身的「进行中 / 已完成」。
- 会话中途报错会把待办标成失败；那匹马之后又跑起来，失败自动作废、状态恢复（终端模式跑的马没有 turn 事件，不会自动恢复，用卡片上的「重连」手动恢复）。
