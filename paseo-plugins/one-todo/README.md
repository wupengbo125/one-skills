# one-todo

Paseo 的待办插件：先把任务记下来，点「全军出击」才真的开 Agent 会话去跑。

## 基本用法

- 侧栏「待办」进入，点「添加」新建。
- 填标题（必填）、内容（要做的事 / 验收标准）。
- 选模式：**普通**（一个工作区）或**赛马**（多匹马各一条分支）。
- 普通模式下选在哪跑：项目（Local 或 Worktree），可另选 Workspace；赛马只能 Worktree。
- 放马：选一个或多个 Provider / Model。
- **长按**「全军出击」1 秒开始。

## 不点不知道的操作

- **长按 1 秒才开跑**：按住「全军出击」，按钮上的进度条填满才启动；中途松手＝取消，短按无效。
- **普通模式就一个工作区**：选 Local 就在你当前目录跑，选 Worktree 就是那条 worktree；放几匹马都挤在这一个工作区里。
- **赛马是唯一多工作区的路**：点「赛马」后必须 Worktree、至少 2 匹马；先开一个主干工作区（项目目录）给审核员落脚，每匹马各一条 worktree 去改代码。
- **模式第一次派马时就定死**，以后加马照原模式走；想换模式就新开一个待办。
- **加马只派新马**：跑过的马列在「已跑过」那行字里（只显示、不给删），下面的框留给这次要派的新马。
  只保存没开跑的马不算老马，仍留在框里可改可删。
- 点 `#序号` 徽标：把「请执行待办任务 #序号《标题》…」复制到剪贴板，并在 进行中 / 未开始 之间切换。
- 点标题：打开编辑。
- 点右侧 `⋮`：置顶 / 删除。
- **进行中**的任务，右边有个小箭头 `↗`：点一下直接跳到它的会话（多个 workspace 时跳第一个）。
- 失败的任务：「重连」回进行中；「重置」回未开始。
- 「已完成」只列当天的，隔天自动收走。
- GitHub Issue 页签：列出本地仓库的 open issue，点「存入待办」收进列表；点条目可配置后开跑。
- 「使用技能」可多选，开跑时填进开场向导词的 `{{Skills}}` 空位（那句原话写在向导词里，可自行删改）。

## 归档时会怎样

- 归档会话 / 归档 Workspace **都不再动任务**：状态、名单、时间一律保持原样。任务完没完由你点完成说了算。
- 把任务**点成完成**才会关 Workspace：长按勾选框，插件先关掉这个任务名下的所有 Workspace（Paseo 归档工作区会连带关掉里面所有会话和终端），关完才标成已完成。
- 某个 Workspace 开跑时若建过分支，**归档它就会删掉它对应的那条分支**（worktree 目录由 Paseo 自己删）。
  多个马各在一个 worktree 时，归档哪个就删哪个的分支，互不影响。
- **归档 = 你确认**：那条分支里没合并的改动会一起丢。留着用的那份请先合并 / 保好。

## 评审

多马各在一个 worktree 跑完后，派一个**评审员**去评：多匹马就挑出最好的一份（把各家好处揉成建议，指定一匹接着改），一匹马就直接给建议。两条路都是同一件事——评审。

- 卡片右侧出现 `⚖`（跑过的任务就有，不只限多马；本地直接跑的也能评）。
- 弹层按马匹数自动切模式，也能手动改：≥2 匹是**多匹马评审**，1 匹或本地目录是**一匹马评审**。
- **需求详情**：弹层里那个「需求详情」框决定评审员看到的需求。右侧两个按钮——`待办` 装待办里的标题+内容，`文档` 装那匹马写的需求清单（`audit-list.md`，放在系统临时目录、路径由插件在派马时指定）的内容；装进来的字可以自己删改。框空着点开始会提示「请先填写需求详情」。你手动提示词已并入这个框。
- 选**评审员**（独立的 Provider / Model）。
- 候选 worktree 目录自动解析：git worktree 按分支（权威）→ `worktrees.dir` → Paseo workspace 目录；目录没了会标红「已失效」。有马就只评马，一匹马都没有才评项目目录本身。
- **主工作区**：赛马待办的主工作区是主干（项目目录）——里面没有马，只给审核员落脚；普通待办的主工作区就是那唯一的工作区，马也在里面。
- **开始评审**＝在待办的主工作区里开一个 Agent：审核员只读候选（只看不改），结果直接显示在弹层里。
  - 多匹马结果首行「胜者: <编号>」+ 逐匹点评 + 改进建议；一匹马结果首行「结论: 通过/不通过」+ 问题清单（阻塞/建议）。
- 弹层里能改**向导词**，几份文档各管一条路：
  - `paseo-plugins/one-todo/prompts/赛马向导词.md`（多匹马）
  - `paseo-plugins/one-todo/prompts/评审向导词.md`（一匹马）
  - `paseo-plugins/one-todo/prompts/整改向导词.md`（发回给干活会话时，包在评审意见前面的那句话）
  - `paseo-plugins/one-todo/prompts/开场向导词.md`（任务开跑前，固定拼在提示词前面的那段话，普通模式那份）
  - `paseo-plugins/one-todo/prompts/赛马开场向导词.md`（赛马模式那份）
  - `paseo-plugins/one-todo/prompts/委员会开场向导词.md`（委员会模式那份）
  开场词按模式分三份，三份待遇完全相同：都入库、都随插件仓库走、各存各的；界面上选了哪种模式就编辑哪一份，派马时按那一单的模式挑对应那份。
  某一模式改了没保存就切到别的模式：改动留成草稿（切回来还在），并提示一次，不会静默丢；关掉弹层则收干净，不留草稿。
  模式判定只有一处：赛马优先，其次委员会，再是普通——界面挑哪份编辑和派马挑哪份拼用的是同一个判断。
  这几份都是插件资产，跟着插件仓库走（换机器也在）。
  框里收起/预览/编辑三态，改完点保存模板；发起前改了没保存会先拦你。
- 结果在弹层里直接看，能一键**发给那匹马继续改**（多匹马发给胜者，一匹马发给它自己），也能**复制**出来自己粘；改完再评一次，形成循环。会话已结束或归档时发回会明确报错，不会往死会话里发。`查看评审会话 ↗` 进评审会话；归档待办的主工作区会作废在跑的评审并删掉评审结果文件（赛马时 ✕ 掉某条马只删那条马，不牵连结论）。
- 评审中改不了状态：评审员跑完只翻评审状态，不动待办本身的「进行中 / 已完成」。
- 会话中途报错会把待办标成失败；那匹马之后又跑起来，失败自动作废、状态恢复（终端模式跑的马没有 turn 事件，不会自动恢复，用卡片上的「重连」手动恢复）。
