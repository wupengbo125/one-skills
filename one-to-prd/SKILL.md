# To PRD

把需求讨论的输出转换为项目的标准 PRD 格式，保存到 `docs/prd/`。

---

## 流程

### 1. 获取需求内容

按优先级获取：

1. 用户指定的文件路径
2. 当前对话中的 grilling 输出（如果刚跑完 one-grill-with-docs-prd）
3. 如果都没有，询问用户提供

### 2. 读取 PRD 模板

读取 `one-grill-with-docs-prd/PRD-TEMPLATE.md`，按模板结构填写。

### 3. 映射转换

将需求内容映射到 PRD 模板的各板块：

- **背景与目标** ← 需求的动机和痛点
- **需求描述** ← 具体的功能和行为
- **需求边界** ← 明确做什么、不做什么
- **待确认与遗留问题** ← 讨论中未解决的问题
- **技术实施方案** ← 高层实现思路（不写代码）

区分三类来源并标注：
- 用户明确决策的
- 从已有系统继承的
- Agent 建议的（需用户确认）

### 4. 保存

检查 `docs/prd/` 下已有编号，按三位序号递增创建 `<序号>-<slug>.md`。

写完后告诉用户：文件路径、关键决策摘要、需要确认的 Agent 决策。

---

## 核心规则

1. **忠实转换**：不增删需求内容，只调整格式。
2. **标注来源**：每项决策标明是用户决策、系统继承还是 Agent 建议。
3. **不写代码**：技术实施方案只写高层思路。
