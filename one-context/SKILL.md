# One Context

统一项目上下文管理技能。生成并维护根目录 `CONTEXT.md`，作为整个项目对 AI 的唯一事实来源。

## 核心原则

1. **一份就够**：替代所有旧的蓝图 (BLUEPRINT)、代码地图 (MAP)、需求文档 (PRD)。开新会话时，Agent 只需要读 `CONTEXT.md`。
2. **人工背景最重要**：AI 自己看代码永远看不出“这个 old 目录不用改”、“这个分支下个月要弃用”。人工编写的业务背景是核心价值。
3. **只写位置，不写实现**：模块说明只写“在哪”，不抄代码实现。代码会变，写了就腐烂。

## 流程

### 1. 自动判断模式

- 根目录无 `CONTEXT.md` → **初始化模式 (init)**
- 根目录已有 `CONTEXT.md` → **更新模式 (update)**

### 2. 初始化 (init)

1. 读取本技能目录下的 `CONTEXT-TEMPLATE.md`。
2. 扫描当前仓库的一级目录和关键入口文件。
3. 询问用户补充**人工背景**（最想告诉 AI 的背景知识，如：项目是干啥的、哪些目录不能动、有什么特殊约定）。
4. 在根目录生成 `CONTEXT.md`。

### 3. 更新 (update)

1. 读取现有 `CONTEXT.md`。
2. 扫描当前物理代码结构，检查是否有新增/删除的模块目录。
3. 对比现有文档，只更新有变动的部分（如新模块位置、新完成的功能）。
4. **绝对不覆盖人工背景小节**，除非用户明确要求修改。

## 完成标准

- 根目录生成或更新了 `CONTEXT.md`。
- 人工背景小节有实质内容（非空模板）。
- 功能位置索引准确指向现有文件/目录。
