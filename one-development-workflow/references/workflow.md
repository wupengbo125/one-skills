# 开发流程详解

## 1. 需求受理（改代码前）

- 把用户需求写下来：做什么、不做什么、边界在哪。
- 需求不清楚就问，不许猜。
- 这份需求文档是后续 code review 需求符合轴的参考文档。

## 2. 开发

- 只按需求改，不动其他文件、其他逻辑。
- 遵守 constitution.md 精准修改铁律。

## 3. 测试

- 能跑测试就跑（单元测试、构建、冒烟验证）。
- 测不了说明原因，不许假装测过。

## 4. Code Review（双 sub-agent）

调用 `one-code-review`，两个 sub-agent 并行：

- **代码质量 sub-agent**：查命名、重复、坏味道。
- **需求符合 sub-agent**：拿第1步的需求文档当参考，重点查：
  - 需求要求但没做的
  - **需求没要求但多做的（范围蔓延）——这是重点**
  - 看似做了实际有误的

主 agent 有记忆偏差，sub-agent 无记忆、拿需求文档看，最准确。

## 5. 需求核对（最终闸门）

对照用户原始需求，逐条核对：

- 我改的每一行，用户需求里包含吗？
- 多出来的功能/重构/优化，用户说了吗？没说就删。
- 核对通过才能交付。

## 失败处理

- code review 查出问题 → 修完重跑 review。
- 需求核对发现多开发 → 立刻删掉多余部分。
- 任何一步不通过，不交付。
