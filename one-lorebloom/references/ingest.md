# 摄入与编译 (ingest)

将 `raw/` 中的原始源材料提炼编译入 `lorebloom/` 持久知识库。
**本地通道**：直接读写 `~/onespace/github/lorebloom`，完成后 git commit + push。

## 目录约定

- `raw/` 根目录：收件箱，待摄入。
- `raw/<领域>/`：已摄入归档，与 `lorebloom/<领域>/` 一一对应。
- `raw/misc/`：不移动、不分类、不摄入，直接保留为原始资料。
- 除 `raw/` 根目录和 `raw/misc/` 外，其他位置是已归档文件，禁止再次扫描。

## 执行步骤

1. **拉取最新**：`cd ~/onespace/github/lorebloom && git pull`。

2. **扫描与计划**：
   列 `raw/` 根目录下的源文件，逐份判断领域（life / study / food / technology / stocks）。新领域先与用户确认，严禁擅自新建。
   `raw/misc/` 下的文件不移动、不分类，跳过。
   简短向用户列出拟新建/更新的页面计划。

3. **读原文，识别核心**：
   这篇原文要传达的那个道理、方法或对象信息。所有抽取围绕核心；用来引出核心的场景与道具是**媒介**（如借乒乓球讲人生道理，乒乓球即媒介）。

4. **判断建页类型**：建页前先判断这个东西是什么——
   - 类别/主题/方法论 → concept（可聚合多个实体）
   - 具体实例 → entity（有独立信息才建页，纯标题条目留在 concept 聚合页里）
   - 一篇原文的浓缩 → summary

5. **三层萃取 + projects**，写入 `lorebloom/<领域>/`：
   - **summaries**：一对一结构化浓缩，完整承载核心，保留要点、数据、步骤、结论；媒介在叙述中自然提及；去掉网页导航/广告/重复；头部写 `> 源文件：[[raw/<领域>/<文件名>|查看原文]]`。
   - **concepts**：核心中的可复用方法论、跨多篇资料出现的思维模型。**单次观点留在 summary 里，不独立建页**。
   - **entities**：核心中的外部对象（人物、工具、产品、地点、食材），页面承载该对象本身的独立信息；仅作为场景出现的对象保持文字提及。
   - **projects**：我的项目，记录状态、进展、待办；核心涉及其他领域已有的项目或页面时，用 `[[双链]]` 指过去。
   - **文件名严禁翻译**：原文是什么语言就用什么语言（中文概念直接用中文名，英文/技术专有名词保留英文），严禁机械转成 kebab-case。
   - frontmatter：`type`、`title`、`description`。
   - **增量更新既有页面**：若新材料关联已有概念或实体，在其对应页面追加新证据、关联或标记观点更新，不重复建页。
   - **跨域双链穿透**：提炼概念与实体时主动穿透挖掘底层通识（如在交易中链接人性哲学，在技术中链接第二大脑），自由跨目录建立 `[[双链]]`。双链在相关内容处自然嵌入，相关链接统一放在「## 相关」标题下。
   - **属性归属正确**：每条信息只放在描述它的那个对象的页面（杨波的擅长放杨波页，药房的电话放药房页）；引用其他实体用 `[[双链]]` 指过去，不把对方的属性复制成自己的。
   - **清单型原文**：原文由多条并列条目组成时（如资源清单、通讯录），每条独立建页；清单全貌由 summary 承载或靠领域 index 聚合，不在单条目页里塞入其他条目。
   - **聚合页由内容语义驱动**：原文内容集中在某个主题（医疗、便民、工具等）时，即使原文没有该主题的标题，也建对应聚合概念页，命名用最准确的领域词；原文有分类标题时优先沿用原文标题。

6. **移动原文**：从 `raw/` 根目录移动到 `raw/<领域>/`，内容保持原样。

7. **维护大纲与流水**：
   更新 `lorebloom/<领域>/index.md` 与 `lorebloom/index.md`。
   向 `lorebloom/log.md` 追加 `## [YYYY-MM-DD] ingest | <主题>`。

8. **提交推送**：`git add -A && git commit -m "ingest: <主题>" && git push`。

## 完成标准

- 每个新建/更新的 summary 只读页面即可掌握原文要点，无需再打开 raw。
- 逐个核对新建页面：每页都承载核心信息，媒介类对象只在 summary 文字里出现。
- concept 页都是可复用方法论、跨资料思维模型或主题聚合页，单次感悟未独立建页。
- 建页类型判断正确：类别/主题建 concept，具体实例有独立信息才建 entity，纯标题条目留在 concept 聚合页。
- 逐个核对 entity 页：每条信息归属正确，引用其他实体用双链、不复制对方属性。
- 聚合页由内容主题驱动，命名准确。
- 文件名与原文语言一致，未被翻译。
- `raw/` 根目录已清空（所有文件移进领域目录），`raw/misc/` 未被改动。
- `git push` 成功。
