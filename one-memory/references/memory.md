# 记忆沉淀指南 (Triple-Memory System)

本项目记忆架构分为**项目随身记忆 (onememory)** 与 **全局中枢海马体 (one-hippocampus)** 双仓驱动，其中项目随身记忆内含**规则轨**与**事实轨**两层。

---

## 〇、三轨边界总表（记录前先判定去向）

| 内容类型 | 去向 | 轨道 |
|---|---|---|
| 用户行为指令、项目运维/构建/排障/协作知识（"以后怎么做"） | `<项目根>/onememory/rules.md`（≤150行） | 规则轨 |
| 本次改动的事实、排查过程、决策结论（"做了什么"） | `<项目根>/onememory/timeline.md` + `tasks/` | 事实轨 |
| 跨项目的个人稳定偏好、身份习惯 | 海马体 `personal/preferences.md` / `personal/profile.md` | 全局轨 |

> 规则轨的排除清单（如"实现细节不记"）所拒绝的内容，落入事实轨 `tasks/` 案卷，信息不丢不重。

---

## 一、项目随身记忆 (`<项目根>/onememory/`)

项目微观案卷与行为规则，随项目 Git 仓库流转，同批原子提交（由本地 `pre-commit` 钩子守护）。

### 1. 规则轨：`onememory/rules.md`
- 项目级行为规则记忆（用户教导 + Agent 发现的项目知识），全项目单文件，上限 150 行，超限触发同类合并。
- 记录规则、排除清单、触发条件与文件模板：见 [rules-memory.md](rules-memory.md)。
- **进入项目首次回复前，若存在 `onememory/rules.md` 必须先读**，作为项目级指令。

### 2. 事实轨结构与定位
- **`onememory/timeline.md`**：全项目单一时间线总流水（全项目一个文件，不按天切分）。
  - 格式：单行按时间顺序列出改动：
    `- YYYY-MM-DD HH:mm [会话ID] 本次改动的核心事实与结论`
- **`onememory/tasks/<会话ID>.md`**：对应会话的任务详尽案卷（每会话一个文件，持续增量维护）。
  - 内容：背景诉求、排查过程、关键决策、代码结论、涉及产物。

### 3. 会话 ID 规则
- 若当前环境已知会话 ID（如宿主注入的 `当前会话ID`）：在流水中标注 `[会话ID]` 并同步维护 `tasks/<会话ID>.md`。
- 若当前环境无会话 ID（未装插件或临时 Agent）：流水不带 ID 前缀，不创建 Task 案卷，严禁伪造假 ID。

---

## 二、全局中枢海马体 (`one-hippocampus`)

跨项目宏观大盘与人格中枢，独立单向记录，彻底废除跨仓 hash 联动。

### 1. 跨项目全天宏观日程 (`memory/<YYYY-MM>/<YYYY-MM-DD>.md`)
- **单次生成，双处落盘**：AI 仅需生成一次改动摘要，同时写入项目 `onememory/timeline.md` 与海马体今日流水，避免多次生成浪费上下文。
- **格式**（项目路径必须以 `~` 开头）：
  `- HH:mm [~/项目完整路径] [会话ID] 改动摘要`

### 2. 全局偏好与画像 (`personal/preferences.md` / `personal/profile.md`)
- 获知稳定偏好时，自动追加 `personal/preferences.md`（按分类一条一条，不按天）。
- 获知用户身份、习惯时更新 `personal/profile.md`。

---

## 三、提交与门禁规则

1. **同批原子提交（项目内）**：修改代码必须同时更新当前项目 `onememory/`，同批 `git commit`。本地 `pre-commit` 门禁会自动拦截未沉淀记忆的代码提交。
2. **规则轨同批但不门禁**：`onememory/rules.md` 的改动与代码同批提交即可，低频且 150 行封顶，不参与门禁强校验。
3. **海马体单向记总账**：向海马体今日文件单向追加宏观时间线行，独立提交，不阻塞、不绑架项目代码。
