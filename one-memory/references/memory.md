# 记忆沉淀指南 (Dual-Memory System)

本项目记忆架构分为**项目随身记忆 (onememory)** 与 **全局中枢海马体 (one-hippocampus)** 双轨驱动。

---

## 一、项目随身记忆 (`<项目根>/onememory/`)

项目微观案卷，随项目 Git 仓库流转，同批原子提交（由本地 `pre-commit` 钩子守护）。

### 1. 结构与定位
- **`onememory/timeline.md`**：全项目单一时间线总流水（全项目一个文件，不按天切分）。
  - 格式：单行按时间顺序列出改动：
    `- YYYY-MM-DD HH:mm [会话ID] 本次改动的核心事实与结论`
- **`onememory/tasks/<会话ID>.md`**：对应会话的任务详尽案卷（每会话一个文件，持续增量维护）。
  - 内容：背景诉求、排查过程、关键决策、代码结论、涉及产物。

### 2. 会话 ID 规则
- 若当前环境已知会话 ID（如宿主注入的 `当前会话ID`）：在流水中标注 `[会话ID]` 并同步维护 `tasks/<会话ID>.md`。
- 若当前环境无会话 ID（未装插件或临时 Agent）：流水不带 ID 前缀，不创建 Task 案卷，严禁伪造假 ID。

---

## 二、全局中枢海马体 (`one-hippocampus`)

跨项目宏观大盘与人格中枢，独立单向记录，彻底废除跨仓 hash 联动。

### 1. 跨项目全天宏观日程 (`memory/<YYYY-MM>/<YYYY-MM-DD>.md`)
每次完成任务或提交代码后，向海马体今日文件自动追加单行宏观流水（不写细节，跨项目全景拼图）：
`- HH:mm [项目名] [会话ID] 一句话宏观改动摘要`

### 2. 全局偏好与画像 (`preference.md` / `system/profile.md`)
- 获知稳定偏好时，自动追加 `preference.md`（按分类一条一条，不按天）。
- 获知用户身份、习惯时更新 `system/profile.md`。

---

## 三、提交与门禁规则

1. **同批原子提交（项目内）**：修改代码必须同时更新当前项目 `onememory/`，同批 `git commit`。本地 `pre-commit` 门禁会自动拦截未沉淀记忆的代码提交。
2. **海马体单向记总账**：向海马体今日文件单向追加宏观时间线行，独立提交，不阻塞、不绑架项目代码。
