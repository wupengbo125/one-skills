# 记忆沉淀指南

## 核心规则

- **每日一个文件**：全部流水写入当天文件 `memory/<YYYY-MM>/<YYYY-MM-DD>.md`，不建主题文件。
- **豆包式流水**：内容为自然语言流水段，记"当天做了什么 + 关键结论 + 待办"，不写过程细节、不写结构化长文。
- **三态记忆（对齐豆包）**：daily 每日流水进 `memory/`；**稳定偏好**追加 `preference.md`；**任务**按会话 ID 存 `tasks/<会话ID>.md`，每会话一个文件，写流水时自动更新当前会话的 task（有则更新，无则新建）。
- **commit 即记**：每次 git commit 前，自动向当天文件追加一段流水（这就是自动上限，不等用户开口）。

## 触发时机

- 每次 commit（代码/配置修改、关键决策、新需求、新偏好）
- 用户说"收工"

## 执行步骤

1. 打开当天文件 `memory/<YYYY-MM>/<YYYY-MM-DD>.md`，不存在则创建，在末尾追加一段流水，**段落末尾标注本次提交 hash**（如「(对应提交 abc1234)」）。
2. 获知用户身份、习惯或喜好时，更新 `system/profile.md`。
3. 获知**稳定偏好**时，追加/更新 `preference.md`（一条一条，不按天）；无对应分类时新建 `## 分类名` 小节，不新建文件、不加新态。
4. **任务管理（会话 ID）**：每次写流水时，用当前会话 ID 管理 task：检查 `tasks/<会话ID>.md` 是否存在，存在则更新过程摘要（追加本次改动），不存在则新建。一个会话 ID 就一个文件，文件内多件不相干的事自行用小节拆分。
5. 同步索引：`python3 ~/onespace/github/one-skills/one-memory/scripts/memory.py sync "<当天文件路径>"`。
6. git commit（此步骤前必须完成 1-5）。

## 每日文件内容格式（与豆包一致）

每次追加一段自然语言流水，**开头标注会话 ID**（如 `[38440483288583938]`），覆盖本次改动、结论、待办，段与段之间用 `---` 分隔。

流水是摘要（summarize），task 是详细。检索流程：查流水/索引 → 拿到会话 ID → 去 `tasks/<会话ID>.md` 找详细过程。

示例：

> [38440483288583938] 用户要求将海马体记忆改为每日一个文件，格式与豆包记忆一致。已重写 memory.md 规程，记录统一追加至 memory/2026-09/2026-09-07.md；commit 时自动记录。
>
> ---
>
> [38440483288583938] 第二段流水...

## 历史文件

改造前的主题文件（`<YYYY-MM-DD>_主题.md`）保留为历史档案，不删除、不合并。
