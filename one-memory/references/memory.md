# 记忆沉淀指南

## 核心规则

- **每日一个文件**：全部流水写入当天文件 `memory/<YYYY-MM>/<YYYY-MM-DD>.md`，不建主题文件。
- **流水**：内容为自然语言流水行，记"当天做了什么 + 关键结论 + 待办"，不写过程细节、不写结构化长文。
- **三态记忆（对齐豆包）**：daily 每日流水进 `memory/`；**稳定偏好**追加 `preference.md`；**任务**：若当前环境已知会话 ID（例如宿主插件注入了当前会话 ID），则存 `tasks/<会话ID>.md`（每会话一个文件，写流水时同步更新）；若当前环境未知会话 ID（未装插件或临时 Agent），则仅记普通每日流水，不建 Task，严禁伪造假 ID。
- **commit 即记**：每次 git commit 前，自动向当天文件追加一行流水（这就是自动上限，不等用户开口）。

## 触发时机

- 每次 commit（代码/配置修改、关键决策、新需求、新偏好）

## 执行步骤

1. 检查是否存在已知会话 ID（如上下文已注入“当前会话ID”）：
   - **有会话 ID**：在当天流水末尾追加带 `[会话ID]` 开头的流水行，并同步创建或更新 `tasks/<会话ID>.md`（更新过程摘要、结论与产物）。
   - **无会话 ID**：在当天流水末尾追加普通流水行，不记录 Task，严禁伪造假 ID。
2. 获知用户身份、习惯或喜好时，更新 `system/profile.md`。
3. 获知**稳定偏好**时，追加/更新 `preference.md`（一条一条，不按天）；无对应分类时新建 `## 分类名` 小节，不新建文件、不加新态。
4. **先提交海马体**：在 `~/onespace/github/one-hippocampus/` 执行 `git commit && git push`，拿到本次 commit hash（如 `1c81185`）。
5. **再提交代码仓库**：回到代码仓库，commit message 必须带 `[memory: <hash>]`（如 `[memory: 1c81185] 实际改动说明`），然后 `git push`。commit-msg hook 会验证 hash 真实存在于海马体仓库，不存在则拒绝提交。

## 每日文件内容格式

每次追加一行流水，**开头标注 task ID（=会话 ID）**（如 `[38440483288583938]`），覆盖本次改动、结论、待办。每件事一行，新的事另起一行，行与行之间用 `---` 分隔。

流水是摘要（summarize），task 是详细。检索流程：查流水/索引 → 拿到 task ID → 去 `tasks/<taskID>.md` 找详细过程。

> [38440483288583938] 用户要求将海马体记忆改为每日一个文件，格式与豆包记忆一致。已重写 memory.md 规程。

> 用户说要把a改成B
