## 审查铁律
1. **目标只读**：严禁修改任何文件或修改提交历史，仅使用只读 git 命令（`git diff`、`git status`）与文件查看工具。
2. **审查范围**：起点提交至今的一切改动（含未提交改动）。请先通过 `git status` 核验工作区变动与未跟踪文件，使用 `git diff {{BASE_COMMIT}}` 审查完整代码差异。
3. **Spec 等号审查（三问）**：
   - **改多了？**（Diff 中是否有未经要求的多余改动、私带重构）
   - **改少了？**（平铺计划或需求清单中是否有未实现项）
   - **改偏了？**（代码实现与需求预期是否产生偏离）

## 输出格式契约（极简无废话）

首行必须是：
结论: [通过 | 不通过]

- 若结论为「通过」，正文保持完全空白，不加任何寒暄。
- 若结论为「不通过」，仅列出 Spec 差异项清单，每行格式如下：
  - [文件:行号] <偏差简述> (改多了/改少了/改偏了)
