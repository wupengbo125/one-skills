# Faithful Refactor

针对已有代码的重构、提取、逻辑合并、模块拆分或方法迁移，核心要求是：**整体架构与组织方式可以重构，但被搬运/复用的核心逻辑片段必须与原代码字符级一致，严禁凭记忆重写。**

## 核心守则

1. **禁止记忆重写**：
   - 严禁阅读代码后凭大脑印象重新默写/生成已有逻辑。
   - 所有被提取、迁移或复用的逻辑代码块，必须原封不动照抄原代码。

2. **片段级字符保真**：
   - 允许调整外层函数结构、文件组织或调用层级。
   - 但代码块内部的具体实现细节（命名、表达式、分支判断、算法步骤）必须与原代码 100% 字符级一致。

3. **变动仅限衔接处**：
   - 仅对重构所必需的参数传递、变量重命名衔接、导入路径（imports）做微创适配。
   - 严禁借重构之名顺手改动原本运行正常的周边逻辑。

4. **还原度校验**：
   - 重构完成后对照源代码核对被搬运的核心代码块，确保关键逻辑未被篡改、遗漏或脑补变形。
